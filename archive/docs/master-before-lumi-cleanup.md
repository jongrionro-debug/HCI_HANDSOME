# 연구 기준

**현재 목적·RQ 분리 방향: 2026-10-14 사용자 동의·설명 반영 · 구체 RQ 문안·평가 설계: Proposed · 기존 비교·평가: 2026-10-04**

이 문서는 프로젝트 목적과 연구 질문의 기준이다. 사용자는 패션 아이템 추천·점진적 취향 이해의 목적과 두 RQ의 분리 방향에 동의하고 문서 반영을 요청했다. 핵심 연구 대상은 **우리가 설계한 메모리 시스템을 활용하는 에이전트가 사용자의 복잡한 패션 취향과 아이템 선호 판단을 얼마나 충실하게 재현하는가**다. 고객 미팅·발표용 코디는 활용 사례이며 연구 대상을 한정하지 않는다. 이 설명을 구체적인 비교 조건·지표·실험 절차의 승인으로 확대하지 않는다.

**시스템 설계 기준 · 2026-10-14:** 사용자가 [LUMI 시스템 설계 보고서](../LUMI_시스템_설계_보고서_수정본.html)를 메인 설계도로 지정했다. 현재 프로젝트 명칭은 LUMI이며 StyleMate는 이전 명칭이다. 이미지로 초기 LOOK을 선택하고 필요할 때 이유 가설을 확인·비교하며 세션 추천을 갱신하는 흐름을 따른다. 보고서의 5개/2:1:2·이미지 Fallback·Hybrid 종료는 제안·실험 항목이다. 이 정리는 아래 RQ의 비교 조건·지표·프로토콜을 새로 승인하거나 연구 효과를 입증하지 않는다. 구현 경계는 [현재 workflow](workflow.md)에서 관리한다.

## Project overview

LUMI(Long&short-term User Memory with Image-selection)는 장기·세션 기억과 현재 요청을 활용하고 이미지 선택·필요한 확인을 통해 사용자 취향에 맞는 패션 아이템과 코디를 찾는 추천 에이전트다. 말로 취향을 정확히 설명하기 어려운 사용자도 적은 질문으로 선호를 발견하도록 돕는 것이 시스템 목표다. 취향을 아이템·조건별로 다루고, 지속적 선호와 현재 요구를 구분하며 장기 활용은 별도 동의를 거친다.

## Project objective

반복 상호작용으로 축적한 취향을 활용하는 메모리 시스템을 설계하고, 이를 기반으로 한 에이전트의 아이템 선호 판단이 사용자의 판단을 얼마나 충실하게 재현하는지 평가한다. 기존 취향을 보존하면서 현재 상황과 그 밖의 요구를 함께 반영해 원하는 아이템을 찾는 것이 목표다.

## 우리가 설계한 메모리 시스템의 연구 범위

연구할 설계는 **아이템·조건별 취향 기록 → 지속적 선호/현재 요구 분리 → 현재 대상에 유효한 기억 조회·충돌 처리 → 목표 속성 추론·검증**이다. 확인한 취향의 내용·적용 범위·근거를 보존하고 장기 활용은 사용자 동의를 거친다. 이 구조를 사용하는 에이전트의 취향 판단을 평가하며, 기억에 적힌 내용을 다시 말하는 것만으로 취향 재현의 성공을 판정하지 않는다.

**‘취향 판단을 재현한다’는 뜻:** 같은 요청 조건에서 사용자가 어떤 아이템을 좋아하거나 선택하는지와 시스템의 판단이 부합하는 것이다. 예를 들어 “상의는 여유핏, 바지는 슬림핏”이라는 기억이 있을 때, 새로 제시된 셔츠와 바지에도 사용자의 선호가 각각 반영되는지를 본다. 현재 코드의 목표 속성 추론과 실제 상품에 대한 선호 판단·추천은 다른 검증 단계다. [현재 실행 범위](shopping-memory-prototype.md)와 [목표 속성 연결 계획](target-feature-inference-plan.md)을 구분한다.

## 메모리와 상호작용의 역할

| 수단 | 목적 |
|---|---|
| 텍스트·이미지 상호작용 | 사용자의 설명, 이미지 선택과 선택 이유, 수정에서 원하는 아이템의 조건과 취향을 파악한다. |
| 단기 메모리 | 현재 요청의 요구·상황·선택과 아직 확인 중인 선호를 다룬다. 이번의 예외를 일반적인 취향으로 확대하지 않는다. |
| 장기 메모리 | 사용자가 확인하고 이후 활용에 동의한 취향을 축적해 다음 요청에도 참고한다. |
| 반복 상호작용 | 기존 기억과 새 피드백을 대조하고 모르는 부분·오해를 확인해 취향 표현을 점진적으로 구체화한다. |

**‘점진적으로 닮아간다’는 뜻:** 반복되는 선택·설명·수정에서 확인한 취향을 축적하고 오해를 수정해, 시스템의 아이템 선호 판단이 사용자 판단에 더 충실해지도록 하는 목표다. 기존 취향의 보존은 영구 고정을 뜻하지 않으며, 사용자가 확인한 지속적 변화와 일시적 요구를 구분한다. 특정 귀납 알고리즘·수학적 수렴·자동 장기 갱신을 확정한 것은 아니다.

**초기 사용자 화면 · 2026-10-14 사용자 지정:** Feature Map·메모리의 채워진 상태와 전체 조건표를 기본 표시하지 않고 이미지 선택·필요한 확인·추천과 수정에 집중한다. 내부의 출처·적용 범위·필수 조건과 내용 확인/이후 활용 동의는 유지한다. 불필요한 정보량을 줄이려는 방향이며 실제 표현 부담·피로도 감소는 미검증이다. 이미지·부분 선택, 미선택을 싫어함으로 취급하지 않는 원칙, 선택적 확인·비교와 사용자 종료권은 LUMI 보고서를 따른다. 기존 RQ 비교·평가와 아래 Proposed 정렬안의 상태는 바꾸지 않는다.

## 문제 정의

연구 대상은 **자신의 취향과 현재 요구에 맞는 패션 아이템을 찾으려는 사용자**다. 상황에 맞춰 코디를 바꾸는 사용자는 그중 하나의 사례다.

1. **복잡하고 부분적으로 드러나는 취향:** “넉넉한 셔츠는 좋아하지만 바지는 슬림 핏을 선호한다”처럼 취향은 아이템과 조건에 따라 다를 수 있다. 한 번의 설정이나 단일 스타일 라벨로 전체 취향을 확정하기 어렵다. 에이전트는 반복 상호작용에서 얻은 근거를 축적해야 한다.
2. **지속적 취향과 현재 요구의 혼동:** “이번에는 다른 색을 찾고 싶다”는 요구를 기본 취향의 변화로 저장하면 다음 추천에도 원하지 않는 조건이 남는다. 기존 취향을 보존하면서 현재 요구를 반영하고, 이후에도 활용할 취향은 사용자 확인·동의로 구분해야 한다.
3. **원하는 아이템을 표현하는 부담:** 핏·색감·질감처럼 원하는 차이를 말로 설명하기 어려울 수 있다. 텍스트 설명과 이미지 비교·선택 이유를 함께 사용해 조건을 구체화할 필요가 있다.

## RQ 정렬안 — Proposed

사용자는 메모리 기반 취향 재현과 상호작용을 통한 취향 파악으로 RQ를 분리하는 방향에 동의했다. 아래 구체적인 문안과 평가 방법은 이를 반영한 **검토안**이다. 새로운 비교 조건·지표·프로토콜은 아직 확정하지 않았으며, 기존 비교 조건을 승인 없이 대체하지 않는다.

### RQ1. 설계한 메모리 시스템을 통한 취향 판단의 재현

**우리가 설계한 장·단기 메모리 시스템을 활용하는 에이전트는 사용자의 패션 아이템 선호 판단을 얼마나 충실하게 재현하는가?**

- 초점: 아이템·조건별 기억과 장·단기 범위, 유효 context와 목표 속성 추론을 사용하는 시스템의 **취향 판단 결과**.
- 평가 제안: 반복 요청에서 취향을 축적한 뒤 평가용 아이템에 대한 시스템 판단과 사용자의 선호·선택을 비교한다. 평가용 응답은 해당 판단 전에 메모리에 넣지 않아 단순 재사용과 구분한다. 확인한 조건의 보존·오류·일시적 조건의 잘못된 이월은 작동 근거로 별도 확인한다.
- 비교 제안: 질문·입력 정보·모델·후보·후보 평가 방식은 같게 두고 메모리 구조와 조회·context 구성만 다르게 한다. 이때 관찰하는 것은 바꾼 구성의 결합 효과이며 메모리 저장소 하나의 효과로 해석하지 않는다. 구체적인 대조 구조·지표·반복 과제는 미정이다.

### RQ2. 텍스트·이미지 상호작용을 통한 취향 파악

**부족한 정보에 맞춰 텍스트 질문과 이미지 비교를 제공하는 방식은 원하는 아이템의 조건을 전달하는 부담과 시스템이 자신의 의도를 이해한다고 느끼는 정도에 어떤 영향을 미치는가?**

- 초점: 사용자가 말·이미지 선택·선택 이유로 현재 원하는 조건을 구체화하는 과정.
- 기존 비교를 참고할 수 있다: 텍스트만 / 텍스트·이미지 고정 순서 / 필요한 정보에 따른 선택 제공. 구체적인 결합·형식 선택·종료 정책은 미정이다.
- 구분: 취향 정보를 **어떻게 얻는가**를 다룬다. 메모리의 누적 효과와 구분해 평가하며, 이해받는 느낌을 실제 추론 정확도의 증거로 사용하지 않는다.

### RQ의 경계와 검증 단계

| 구분 | RQ1 | RQ2 |
|---|---|---|
| 연구할 요소 | 설계한 메모리 구조·조회·context를 활용한 취향 판단 | 텍스트·이미지로 취향 정보를 얻는 방식 |
| 핵심 결과 | 같은 요청 조건에서 사용자와 시스템의 아이템 선호 판단이 부합하는가? | 원하는 조건을 전달하기 쉽고 이해받는다고 느끼는가? |
| 고정할 요소의 제안 | 질문 형식·입력 정보·모델·후보 평가 방식 | 메모리 구조·조회·목표 추론·모델·후보 평가 방식 |

현재 구현으로 확인할 수 있는 **기억/context·목표 속성의 충실성**은 필요 조건이다. 핵심 목표인 **평가용 아이템의 선호 판단·추천과 사용자 판단의 부합**은 상품 후보와 평가 경로를 마련해 별도로 검증해야 한다. 두 결과를 같다고 보고하지 않는다. 조건 차이를 유지한 여러 요청과 아직 평가하지 않은 아이템을 활용하는 것은 평가 제안이며, 사용자 취향이 변화할 수 있으므로 해당 요청 시점의 사용자 판단을 기준으로 삼는다.

## 기존 RQ의 비교·평가와 새 목표의 관계

2026-10-04에 정한 아래 비교·주 평가는 기존 확정 기록으로 보존한다. 새 목적과 관련된 상호작용을 평가하지만, 이 결과만으로 반복 사용에 따른 취향 표현의 개선이나 실제 아이템 추천 품질을 입증할 수는 없다.

| 기존 RQ | 기존 비교 | 기존 주 평가 |
|---|---|---|
| RQ1 · 선호 분리·확인·수정 | 기본/일시 선호를 구분하지 않음 ↔ 별도 관리와 사용자 확인·수정 | 추천 조건·방향을 조정할 수 있다는 통제감(사용자 주도성). 분리·확인·수정의 결합 효과이며 각 기능의 단독 효과가 아님 |
| RQ2 · 선택적 텍스트·이미지 제공 | 텍스트만 / 텍스트·이미지 고정 순서 / 필요한 정보에 따른 선택 제공 | 의도 표현 부담, 이해받는 느낌. 소요 시간·질문 수는 보조 지표 |

## 중간보고서의 현재 상태와 남은 결정

[현재 프로토타입](shopping-memory-prototype.md)은 장·단기 메모리, 유효 조건 조회, 아이템의 목표 속성 추론·검증과 CLI를 구현했다. 제품 UI·이미지 처리·상품 검색/추천·아이템 선호 판단 평가와 사용자 비교 평가는 후속 범위다. 우리 메모리 시스템이 사용자 취향 판단을 재현하거나 반복 사용으로 개선된다는 사용자 연구 결과는 아직 없다.

다음에는 구체적인 RQ 문안과 대조 메모리 구조, 반복 요청·평가용 아이템과 선호 판단 지표, LUMI의 질문·비교·종료 정책을 평가할 조건, 설문·참여자·실험 절차를 정해야 한다. 기존 [연구 조사](research-landscape.md#h-문서의-rq를-검증하는-방법과-읽기-순서)와 [보관된 Figma 흐름](archive/stylemate-workflow.md)은 이전 RQ와 코디 사례의 참고 기록이다. 해당 사례를 현재 프로젝트 전체의 대상으로 해석하지 않는다.
