StyleMate는 텍스트·이미지 상호작용과 우리가 설계한 장·단기 메모리 시스템으로 아이템·조건별 취향을 축적하고, 기존 취향과 현재 요구에 맞는 패션 아이템을 찾는 에이전트를 목표로 한다. 이 시스템을 활용한 아이템 선호 판단이 사용자의 판단을 얼마나 충실하게 재현하는지 연구한다.

목적 범위 · 2026-10-14: 아래 Figma 화면과 코디 흐름은 기존 설계 사례다. 고객 미팅·발표 등 특정 상황의 코디 조정으로 프로젝트 전체를 한정하지 않는다. 사용자 동의를 반영한 목적·RQ 분리 방향과 구체 문안·평가 검토안은 연구 기준을 따른다. 취향 판단 재현은 연구 목표이며 새 상품 추천 UI나 효과의 구현·검증을 뜻하지 않는다.

현재 초기 UI 방향 · 2026-10-14 사용자 지정: Feature Map과 메모리의 채워진 상태·전체 조건표·채움률·확정/추론 표시는 사용자 화면에 기본 노출하지 않는다. 사용자는 짧은 질문, 선택 버튼, 비교 이미지, 추천과 수정 동작으로 취향을 표현한다. 기존 오른쪽 조건 패널은 Figma 참조 기록이며 현재 초기 UI의 필수 구성이 아니다. 상세 표시 원칙은 D절을 따른다. 정보량을 줄이려는 설계 의도이며 실제 피로도 감소를 검증한 결과는 아니다.

A

전체 흐름과 문서의 근거

위 연결은 화면의 단계 번호와 버튼 문구를 바탕으로 정리한 설계 흐름이다. 실행 중인 제품이나 모든 클릭 연결을 검증한 결과는 아니다.

단계 Figma 근거 화면 확인한 주요 동작
01 Login 계정으로 시작하고 초기 설정 방식을 선택한다.
02A Direct Input 평소 스타일을 글과 키워드로 표현한다.
02B Image Select 마음에 드는 스타일 이미지 2–4개를 고른다.
02C Learn Together 초기 취향을 확정하지 않고 사용하면서 알아간다.
03 Current Request 이번에 원하는 스타일이나 아이템을 입력한다.
04 Adaptive Interaction 채팅과 이미지로 조건을 좁히고 파악한 내용을 보여준다.
05 Follow-up Preference 선택한 이미지의 어떤 요소를 좋아하는지 묻는다.
06 Final Recommendation 추천 방향과 이유를 비교하고 코디를 선택한다.
07 Selective Memory 기본 취향으로 저장할 요소를 선택한다.

근거의 범위: 저장소의 Figma 링크가 가리키는 Web Flow V2 · StyleMate Reference의 9개 화면을 확인했다. 연구 목적과 선호 분리 원칙은 master.md를 따른다. Assignment/Readme.md에 따라 과제 PDF 두 개는 기준 자료에서 제외했다.

표기 원칙: 기존 Figma 화면의 구성, 승인된 메모리 설계, 후속 UI의 구현 제안·미정을 구분한다. 이 문서는 제품 화면의 설계이며 현재 실행 앱의 명세가 아니다. 최신 Figma를 이번 문서 정리에서 다시 검증하지 않았다.

메모리 상세 설계 상태 · 2026-10-14 확인: Issue #1의 장·단기 메모리 설계와 구현 계획은 범위·확인·동의·조회·충돌·보관·삭제·처리 계약을 정의한다. ADR 0001/0002와 v0.2 계약은 Accepted — 2026-10-13 사용자 전체 승인이다. 아래 승인된 조작은 UI가 구현됐다는 뜻이 아니다.

현재 실행 범위: 후속 Issue #2에서 Python·SQLite·CLI 기반 메모리/context·쇼핑용 17개 목표 feature와 LLM 연결 코드를 구현했다. 현재 실행 문서와 ADR 0003이 축소된 실행 계약의 기준이다. v0.2와 실행 DTO는 동일한 JSON 형식이 아니다. 로그인·이미지 해석·상품 추천·전체 UI는 구현 범위 밖이며 실제 LLM 호출은 나중으로 정했다.

B

로그인과 세 가지 초기 취향 설정 경로

로그인 화면에는 Google·Apple 로그인, 이메일·비밀번호 입력, 로그인 상태 유지, 회원가입이 있다. 로그인 이후 초기 설정 방식을 고르는 A·B·C 버튼이 있다. 인증 제공자의 실제 연결은 확인하지 않았다.

경로 사용자 행동 시스템이 얻는 정보 다음 단계
A · 직접 입력 평소 좋아하는 스타일을 자유롭게 적는다. 추천 키워드도 참고한다. 스타일·핏·색상 등에 대한 명시적 설명 다음으로를 거쳐 현재 요청으로 합류
B · 이미지 선택 미니멀·캐주얼·스트릿·포멀 등 이미지 중 2–4개를 선택한다. 선택한 이미지와 확인할 스타일 요소 후보 다음으로를 거쳐 현재 요청으로 합류
C · 사용하면서 알아가기 아직 잘 모르겠어요 경로에서 바로 시작하기를 누른다. 아직 정해지지 않은 취향 현재 요청과 이후 상호작용에서 취향을 구체화

직접 입력 예시는 스트릿·오버핏·무채색·신발의 작은 포인트를 언급한다. 이미지 경로는 선택된 카드에 파란 테두리와 체크 표시를 보여준다. C 경로는 대화와 이미지 선택으로 취향을 알아간다고 안내한다.

승인된 메모리 설계: 세 경로를 같은 기억 구조로 정리하되 직접 입력·이미지 이유를 항목별로 확인한다. 이후 활용할 요소는 기본 미체크 상태에서 선택·저장하며, C 경로는 빈 기본 취향으로 시작한다. 요청 원문과 장기 동의 snapshot의 보관은 분리한다. 초기 설정 UI의 구현은 후속 범위다.

UI 미정: 초기 설정 화면에는 1–4 진행 표시가 있고 나머지 화면 연결은 확인되지 않았다. 항목 검토·저장 시점과 빈 프로필 경로는 승인된 메모리 설계를 따른다.

C

현재 요청과 공통 작업 공간

사용자는 오늘 어떤 스타일을 찾고 계신가요? 화면에서 이번 목표를 입력한다. 텍스트 입력, 이미지 첨부, 음성 입력, 예시 요청 버튼이 표시되어 있다. 요청 시작하기와 입력창의 전송 버튼이 요청 진입점이다.

화면 예시는 가을 아우터, 편한 데일리룩, 면접 복장, 검정 바지에 어울리는 상의다. 이 요청은 평소 취향과 별도로 이번 추천의 목표가 된다.

아래 작업 공간은 기존 Figma의 구성 기록이다. 오른쪽 조건 패널과 기본 취향 현황의 기본 노출은 현재 초기 UI 방향에 적용하지 않는다.

작업 공간
  • 상단 탐색Home · Chat · My Style, 초기 화면에는 Explore도 표시
  • 왼쪽 요청 목록새로운 스타일 요청 · 이전 요청
  • 왼쪽 내 스타일내 기본 스타일 · 저장한 아이템 · 최근 본 아이템 · 설정
  • 중앙 영역요청 입력 또는 대화와 이미지 후보
  • 오른쪽 조건 패널적응형 대화에서 지금까지 파악한 내용

승인된 메모리 설계: 사용자의 비어 있지 않은 전송을 수락할 때 새 요청 ID를 만들고 이번 조건을 별도 상태로 시작한다. 이전 임시 조건은 자동 이월하지 않는다. 같은 요청 재개·새 요청·선택 복제를 구분하고, 재개 시 만료된 날짜·상황을 재확인한다. 상세 수명 계약은 메모리 설계 D02에 있다.

요청 화면은 사진과 대화를 추천에 필요한 범위에서 사용한다고 안내한다. 이 문구만으로 서버 보관 기간이나 대화 삭제 방식을 확정할 수는 없다.

UI 미정: 이미지·음성의 실제 처리, 전송 버튼과 시작 버튼의 연결은 후속 UI 범위다. 빈 입력 거부와 보관 중 동일 요청 재개는 승인된 메모리 계약에 정의했다. 저장 아이템·최근 본 아이템의 상세 화면은 이 범위 밖이다.

D

적응형 대화와 추천 조건의 분리

기존 Figma에서 중앙 채팅은 사용자의 말을 받고 이미지 후보를 제시한다. 오른쪽 지금까지 파악한 내용에는 내 기본 스타일(읽기)와 이번 요청(쓰기)가 표시된다. 계절·아이템·무드와 아직 파악 중인 핏·컬러·기장감·추가 디테일을 보여준다. 이 패널은 현재 초기 UI에서 기본 표시할 대상으로 정하지 않는다.

화면 예시에서는 가을 아우터 요청 뒤에 후보 이미지를 보여준다. 사용자는 이미지를 선택하고, 마음에 드는 요소로 색감·핏·분위기·소재·디테일 중 하나를 고른다. 자유 입력으로 조건을 추가할 수도 있다.

현재 초기 UI의 표시 원칙 — 2026-10-14

사용자는 질문에 답하고, 이미지·아이템을 고르고, 마음에 들지 않는 부분을 수정한다. Feature Map과 메모리는 이를 처리하는 내부 상태다. 전체 속성 목록, 채움률, 장·단기 메모리 목록, 조건 요약 패널과 확정/추론 배지는 초기 사용자 화면에 기본 표시하지 않는다. 속성 설명은 해당 질문에 필요한 짧은 문장으로 제공하고 긴 텍스트 입력을 강제하지 않는다.

이미지 비교는 이미 파악한 조건에 맞는 라벨링된 아이템에서 이번에 확인할 속성의 값이 다른 후보를 고르는 방향이다. 질문에서 비교할 요소를 알리고, 선택은 해당 요소에만 반영한다. 다른 속성·촬영 차이는 가능한 한 줄인다. 실제 라벨 데이터·이미지 검색/선정·후보 부족 시 대체 규칙은 아직 구현·검증하지 않았다.

내부에서는 사용자 직접 입력/선택과 모델 추정의 출처, 필수 조건, 적용 범위와 사용 근거를 유지한다. 추정값은 추천에 활용할 수 있지만 자동으로 필수 조건이나 장기 취향으로 확정하지 않는다. 사용자가 반대하지 않았다는 사실만으로 내용 확인·이후 활용 동의를 완료하지 않는다. 해석이 모호하거나 조건이 충돌할 때는 관련 요소만 짧게 확인하며 전체 내부 상태를 설명하게 하지 않는다.

장기 활용 동의·수정·철회·삭제의 기존 계약은 유지한다. 예를 들어 이후 활용을 확인할 때 해당 요소만 “이런 핏을 다음에도 참고해도 될까요?”처럼 묻고, 전체 메모리 목록을 보여줄 필요는 없다. 동의의 정확한 대상·의미 확인과 관리 동작의 UI/이벤트 연결은 후속 구현 대상이다. 현재 방향은 기본 노출을 줄이는 결정이며 사용자 관리 권한의 제거를 뜻하지 않는다.

이 표시 방향은 사용자가 지정했다. 정보량 감소가 표현 부담을 낮추는지, 추천을 수정하기 쉬운지는 사용자 평가로 확인해야 한다. 기존 RQ 비교·주 평가와 Proposed 정렬안은 이 결정만으로 바꾸지 않는다.

구현 제안 — 다음 상호작용을 고르는 규칙:

필요한 정보 제공할 상호작용 반영할 상태
일정·활동·이동량처럼 사실 확인이 필요한 조건 짧은 텍스트 질문 이번 요청의 상황 조건
단정함·격식·실루엣처럼 말로 표현하기 어려운 경계 차이를 비교할 수 있는 이미지 선택 이번 요청의 스타일 조건
이미지를 좋아하는 이유 요소 선택과 짧은 추가 질문 선택한 요소에 대한 명시적 피드백
서로 충돌하거나 불명확한 조건 해석을 보여주고 확인 질문 확인된 조건으로 수정
사용자가 추천받기를 선택한 상태 현재 조건으로 추천 추천 결과와 반영 이유

승인된 메모리 설계: 이번 요청의 응답은 기본 취향을 자동으로 덮어쓰지 않는다. 조건 변경 뒤 이전 추천은 갱신 필요로 표시한다.

기존 Figma 기반 UI 제안: 사용자가 새 조건을 보내면 대화와 조건 패널을 함께 갱신하고 현재 조건으로 후보를 다시 계산하는 방식이었다. 현재 초기 UI에서는 내부 조건과 후보를 갱신하되 전체 조건 패널을 기본 노출하지 않는다.

연구 기준: RQ2는 추가 정보가 필요할 때 텍스트와 이미지를 선택적으로 제공하는 방식이다. Figma의 가을 아우터 예시 순서를 모든 요청에 고정 적용하면 이 기준과 달라진다.

미정: RQ2의 질문 종료 조건·형식 선택과 후보 이미지 공급은 별도 정책이 필요하다. 메모리 설계는 확인 중·기본·이번 조건, 이번 요청 제외·장기 수정·철회·삭제의 승인된 조작 계약을 정의한다. 현재 Figma에서 이 조작들을 구현 확인한 것은 아니다.

E

이미지 선택 뒤에 세부 취향을 확인하는 방식

세부 취향 화면은 왼쪽에 선택 이미지와 대체 이미지 썸네일을 크게 보여준다. 오른쪽은 질문, 요소 선택, 대화, 새 후보 이미지로 구성된다.

  1. 사용자가 후보 이미지를 선택한다.
  2. 시스템이 어떤 부분이 마음에 드는지 묻는다.
  3. 사용자가 색감·핏·디자인 디테일·소재·전체 분위기를 고른다.
  4. 사용자가 추가 조건을 글로 설명한다.
  5. 시스템이 선택한 요소를 기준으로 변형 후보를 보여준다.
  6. 사용자가 조건을 더 보내거나 추천 결과 보기를 누른다.

화면 예시는 핏 선택과 함께 색감·편안함에 대한 텍스트 피드백을 보여준다. 다음 후보에는 Recommended 표시가 있다. 이전으로 버튼도 표시된다.

승인된 메모리 설계: 이미지 선택 자체와 선택 이유를 분리해 기록한다. 사용자가 핏을 선택했다고 이미지의 색상·소재·격식까지 모두 좋아한다고 확정하지 않는다. 글로 추가한 조건도 확인된 범위에서 반영한다.

승인된 메모리 설계: 복수 요소 선택을 허용한다. 이미지를 바꿔도 확정된 요소는 근거 이미지와 함께 유지하고 새 이미지 속성으로 자동 변경하지 않는다. 이전 화면으로 돌아가도 확정 조건은 유지한다.

UI 미정: 세부 취향 확인을 별도 화면으로 제공할지, 채팅 내부에서 확장할지는 후속 UI 선택이다.

F

최종 추천에서 비교하고 선택하기

최종 추천 화면은 다음 세 방향을 나란히 보여준다. 각 카드에는 이미지, 설명, 조건 태그, 행동 버튼이 있다.

추천 방향 화면의 의미 주요 행동
A · 데일리 무드 평소 스타일과 자연스럽게 어울리는 코디 자세히 보기
B · 추천 코디 현재 요청과 취향을 균형 있게 반영한 조합 이 코디 선택
C · 새로운 시도 평소보다 다른 무드를 시도하는 코디 자세히 보기

필터는 전체(3), 평소 스타일 기반(2), 새로운 스타일 제안(1)이다. 이 숫자는 현재 화면의 예시 구성이다. 모든 요청에서 같은 추천 개수를 제공해야 한다는 규칙은 아니다.

구현 제안: 각 결과에 사용한 기본 취향과 이번 요청의 조건을 연결한다. 설명에서는 유지한 취향과 상황 때문에 조정한 요소를 구분한다. 사용자가 코디를 선택한 뒤에는 새로 파악한 취향의 저장 선택으로 이어진다.

현재 요구 중 하나인 상황을 반영한 설명 예시는 다음과 같다. “기본 취향인 여유 있는 핏을 유지했습니다. 고객 미팅에 맞춰 상의를 더 단정하게 조정했습니다.” 이 문장은 Figma의 실제 추천 문구가 아니다.

미정: 자세히 보기의 내용, 다른 카드의 코디 선택 방법, 재추천 조작이 필요하다. 상품 상세·구매·결제 흐름은 현재 화면에서 확인되지 않았다.

G

선택적 기억과 이번 요청만의 조건

추천 이후 모달은 이번 대화에서 새롭게 파악한 요소들을 보여준다. 사용자는 앞으로도 추천에 쓸 요소를 선택한다. 화면에는 가벼우면서 편한 선호, 오버핏 아우터 선호, 차분한 컬러 선호가 체크 항목으로 표시된다.

별도 영역은 이번 요청에만 적용할 요소(저장하지 않음)을 보여준다. 화면 예시는 기존 시즌과 이전에 본 이미지다. 모달은 선택한 요소만 내 기본 스타일에 저장된다고 안내한다.

사용자 행동 기본 취향에 미치는 영향 이번 요청
저장할 취향 요소를 선택·해제 아직 변경하지 않음 현재 조건 유지
선택한 요소 저장하기 선택한 요소를 기본 취향에 반영 기존 결과를 유지하되 갱신 필요 표시
이번에만 적용하기 기본 취향 변경 없음 이번 요청에만 적용
모달 닫기 기본 취향 변경 없음 승인된 설계: 현재 조건을 유지하고 대화로 복귀

승인된 메모리 설계: 기본 취향 변경은 선택한 항목의 내용 확인·이후 활용 동의와 시스템 검증이 성공할 때 수행한다. 체크 기본값은 해제, 전부 해제하면 저장 버튼은 비활성이다. 충돌은 전후와 범위를 확인하며, 복수 항목은 한 배치로 전체 성공 또는 전체 실패한다. 실패하면 선택을 유지하고 실제 결과를 표시한다. 저장 UI의 구현은 후속 범위다.

주의할 의미: 저장하지 않음은 여기서 기본 취향으로 저장하지 않는다는 뜻이다. 대화 기록이나 요청 이력까지 서버에 전혀 보관하지 않는다는 뜻으로 해석하지 않는다.

계약 참조: 저장·중복·충돌·닫기·실패는 메모리 설계 D04–D09를 따른다. 기본 저장을 선택하지 않기, 추천 활용 철회, 실제 기록 삭제는 서로 다른 조작이며 보관·삭제 안내는 D10을 따른다. 화면에 체크된 예시가 있다는 사실을 기본 체크 정책으로 해석하지 않는다.
