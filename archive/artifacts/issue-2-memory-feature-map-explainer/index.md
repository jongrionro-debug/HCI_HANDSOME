**평소 취향과 이번 요청을 따로 저장하고, 이번 아이템에 맞는 목표 조건을 만듭니다.**
보내주신 [issue #1](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/1)은 메모리 설계입니다. [issue #2](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/2)는 그 설계를 실행 코드로 만든 작업입니다. [PR #3](https://github.com/jongrionro-debug/HCI_HANDSOME/pull/3)은 병합됐고 issue #2는 종료됐습니다.

## A 가장 중요한 변화: 오늘만 바꿀 수 있습니다

가상 사용자의 기본 취향은 여유 있는 핏(Relaxed) + 네이비(Navy)입니다.
오늘은 미팅에 입을 바지만 슬림 핏(Slim)으로 바꿉니다.

| 시점 | 이번 바지의 목표 | 기본 취향 |
|---|---|---|
| 평소 취향 저장 | Relaxed · Navy | Relaxed · Navy |
| 오늘 요청에 Slim 추가 | **Slim · Navy** | Relaxed · Navy 유지 |
| 새 쇼핑 요청 시작 | **Relaxed · Navy** | Relaxed · Navy 유지 |

```callout ok 실제 데모에서 확인한 동작
오늘의 예외는 오늘 요청에 적용됩니다. 새 요청에는 이전 요청의 임시 조건이 자동으로 넘어가지 않습니다.
추론 전후에도 저장된 기억은 그대로였습니다.
```

이 표는 실제 실행한 오프라인 가상 데모의 결과입니다.

## B 기억이 목표 조건이 되는 과정

**메모리**는 저장한 취향과 요청 조건입니다.
**context**는 이번 아이템에 사용할 유효한 기억을 모은 묶음입니다.
**목표 feature**는 원하는 옷의 속성입니다. 예를 들어 바지의 핏과 색입니다.

```flow TB
[(기억 저장소)] -> 기억 선별: 현재 요청과 대상
기억 선별 -> 목표 제안: 유효한 context
목표 제안 -> 결과 검증: 규칙 또는 모델
결과 검증 -> *목표 조건: 직접값과 제안 결합
```

기억을 선별할 때 아래 조건을 확인합니다.

- 같은 사용자이며, 이번 요청에 사용할 수 있는가?
- 확인된 활성 기억이며, 아직 유효한가?
- 이번 아이템과 상황에 적용되는가?
- 현재 예외나 충돌 때문에 따로 처리해야 하는가?

예를 들어 **셔츠는 흰색, 바지는 네이비**라는 조건을 대상별로 나눕니다.
철회·삭제·만료된 기억과 다른 요청의 단기 기억은 제외합니다.

## C 이번 조건과 기본 취향은 어떻게 저장하나요?

```flow LR
(미확인 후보) -> 확인된 단기 기억: 내용 확인
확인된 단기 기억 -> [(장기 기억)]: 이후 활용에 별도 동의
```

| 종류 | 의미 | 필요한 근거 |
|---|---|---|
| 미확인 후보 | 아직 사용자가 확인하지 않은 내용 | 실행 조건에서 제외 |
| 확인된 단기 기억 | 이번 요청에서 사용할 조건 | 내용 확인 |
| 장기 기억 | 이후 요청에도 사용할 기본 취향 | 내용 확인 + 이후 활용 동의 |

확인과 장기 활용 동의는 별개입니다. 명시한 취향을 처음부터 장기로 저장할 때도 둘 다 필요합니다.
사용자는 항목을 교체하거나, 활용을 철회하거나, 삭제할 수 있습니다.

```callout info 저장을 지키는 규칙
여러 변경은 모두 성공하거나 모두 취소됩니다. 중간 실패로 일부만 저장되지 않습니다.
같은 저장 명령을 재시도해도 중복 적용하지 않습니다. 오래된 버전으로 수정하면 충돌을 알립니다.
```

현재 구현에서는 호출 코드가 확인·동의의 근거를 전달합니다. 확인 화면과 로그인은 후속 구현 범위입니다.

## D 목표 feature는 17개로 줄였습니다

**모든 속성을 채울 필요는 없습니다.** 관련된 조건만 사용하고 나머지는 미정으로 남깁니다.
원래 계획의 아이템 65개·코디 9개 속성을 일반 쇼핑용 17개로 축소했습니다.

| 쉽게 묶어 보면 | 구현된 속성 |
|---|---|
| 옷의 종류와 형태 · 5개 | 아이템 종류, 전체 핏, 기장, 소매 길이, 넥라인 |
| 보이는 인상 · 6개 | 기본 색상, 무늬, 로고 크기, 스타일, 분위기, 격식 정도 |
| 소재와 사용 환경 · 6개 | 원단, 표면 질감, 계절, 두께, 보온성, 기능 |

이 분류는 설명을 위한 묶음입니다. 코드의 속성 사전은 `registry.py` 한 곳에서 관리합니다.

**상황과 목표 속성도 구분합니다.** 미팅·활동·쇼핑 목적은 상황 정보입니다.
“미팅”이라는 이유만으로 사용자의 필수 조건을 자동으로 만들지 않습니다.
“방수 기능을 원함”은 목표 조건이며, 실제 상품의 방수 성능을 확인한 결과는 아닙니다.

## E 확정된 값과 추론한 값을 구분합니다

가상 데모는 오늘의 목표를 `smart casual`로 확인한 뒤, 규칙으로 격식 정도 3을 제안합니다.
아래 다섯 행은 실제 가상 데모 결과입니다.

| 오늘 바지의 속성 | 값 | 상태와 의미 |
|---|---|---|
| 핏 | Slim | **지정됨** · 사용자가 확인한 직접 조건 |
| 색 | Navy | **지정됨** · 확인한 기본 취향 |
| 격식 정도 | 3 / 5 | **추론 제안** · 확인된 목표를 바탕으로 제안 |
| 원단 | 값 없음 | **미정** · 근거 없이 채우지 않음 |
| 소매 길이 | 해당 없음 | **비적용** · 바지에 적용되지 않음 |

같은 우선순위의 조건이 충돌하면 **충돌 상태와 확인 질문**을 남깁니다. 임의로 하나를 고르지 않습니다.
이 충돌 동작은 데모 표와 별도로 테스트했습니다.

```callout info 목표 조건은 상품 검색의 입력이 됩니다
반환값은 아이템별 속성·제약·근거·질문입니다.
실제 상품 목록이나 완성된 코디를 반환하는 기능은 이번에 구현하지 않았습니다.
```

## F 모델은 제안하고, 시스템이 규칙을 지킵니다

| 상황 | 구현된 처리 |
|---|---|
| 모델이 사용자 직접 조건을 빠뜨림 | 시스템이 직접 조건을 보존 |
| “검정은 피하고 싶다”는 조건 | 회피 조건 유지. 다른 색으로 임의 치환하지 않음 |
| 모델이 값·대상·근거를 잘못 반환함 | 검증에서 거부 |
| 모델이 취향을 자동으로 장기 저장하려 함 | 모델에 메모리 쓰기 권한을 주지 않음 |
| 응답을 기다리는 동안 기억이 철회·변경·만료됨 | 최신 context와 비교해 오래된 결과를 폐기 |

모델의 결과는 **약한 추론 제안**으로 다룹니다. 사용자의 확인이나 필수 조건으로 승격하지 않습니다.

```sequence
앱 -> 저장소: 현재 상태 조회
앱 -> 제안기: 유효한 context 전달
제안기 --> 앱: 목표값 제안
앱 -> 저장소: 최신 상태 다시 조회
note 앱: 상태가 바뀌었으면 결과 폐기
```

기본 실행은 오프라인 규칙을 사용합니다. OpenAI 연결 코드는 만들었으며, 가상 HTTP 응답으로 검사했습니다.
실제 모델 호출과 언어 해석 품질 평가는 남아 있습니다.

## G 코드에서는 어디를 보면 되나요?

| 파일 | 쉬운 역할 |
|---|---|
| `store.py` | SQLite에 요청과 기억 저장. 확인·동의·수정·철회·삭제 처리 |
| `context.py` | 이번 대상에 쓸 기억 선별. 현재 예외·상황·충돌 처리 |
| `registry.py` | 17개 속성의 이름·허용값·적용 대상 관리 |
| `inference.py` | 제안을 검사하고 직접 조건과 합쳐 목표 조건 생성 |
| `llm.py` | 외부 모델 연결과 응답·오류 검사 |
| `app.py` | 전체 과정 연결. 응답 뒤 최신 상태 재확인 |
| `cli.py` | 터미널 실행과 가상 데모 제공 |

읽는 순서는 `app.py` → `context.py` → `inference.py`가 편합니다.
저장 규칙이 궁금하면 `store.py`를 확인하면 됩니다.

## H 어디까지 확인했나요?

이번 설명을 만들면서 로컬 코드를 다시 실행했습니다.

| 확인한 항목 | 실제 결과 |
|---|---|
| 오프라인 단위·통합 테스트 | ok 79개 통과 |
| 오늘 요청 / 새 요청의 핏 | ok Slim / Relaxed |
| 추론 전후 저장 기억 | ok 변하지 않음 |
| 실제 LLM 호출 | no 실행하지 않음 |

테스트는 SQLite 저장, 대상별 context, 목표값 검증, 가상 모델 연결을 확인합니다.
79개 테스트 통과가 실제 모델의 의미 정확도나 사용자 연구 효과를 증명하지는 않습니다.

**남은 제품 기능:** 대화·확인 화면, 로그인, 이미지 속성 추출, 상품 검색·코디 조합, 실제 모델 평가.

저장소 루트에서 아래 명령으로 같은 가상 데모와 테스트를 실행할 수 있습니다.

```sh
PYTHONPATH=src python3 -m stylemate_memory.cli demo --synthetic
PYTHONPATH=src python3 -m unittest discover -s tests -q
```

이 페이지는 구현 설명 자료입니다. 기준은 [issue #2](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/2), [PR #3](https://github.com/jongrionro-debug/HCI_HANDSOME/pull/3), 위 실행 계약과 코드입니다.
