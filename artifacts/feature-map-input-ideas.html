A

먼저 구분할 것: 옷의 속성과 사용자의 의도

아이템 feature map은 옷을 설명한다. 사용자 맥락은 그 옷을 왜, 언제, 어떻게 원하는지 설명한다. 같은 fit이라도 “사진의 바지는 여유 핏”과 “나는 여유 핏을 원한다”는 서로 다른 정보다.

필요한 정보 주된 입력과 근거 추천에 쓰는 방식
아이템 종류·보이는 색·실루엣·기장 아이템 이미지와 상품 설명 텍스트 아이템의 관찰·추출 후보로 정리
실제 소재·착용감·보유 여부 상품 정보 또는 사용자 텍스트 사진만으로 확정하지 않고 확인한 정보로 보완
일정·활동·피하고 싶은 조건 사용자 텍스트 또는 짧은 선택 버튼 이번 요청의 상황·제약으로 적용
원하는 핏·색·격식의 정도 명확한 텍스트, 또는 이미지 비교와 선택 이유 사용자가 지정한 요소만 이번 조건으로 적용
다음에도 쓸 취향·반복 상황 내용 확인과 이후 활용 동의 memory layer의 장기 기억으로 저장

예를 들어 검정 재킷 사진에서 검정색이 관찰될 수 있다. 사용자가 “이 핏이 좋아요”라고 하면 핏만 취향으로 확인한다. 색상 선호와 재킷 보유 여부는 별도로 남긴다.

공통 원칙

feature map의 모든 칸을 사용자에게 채우게 하지 않는다. 아이템 정보는 공급 측 데이터와 이미지에서 얻고, 사용자는 목적·제약·선택 이유를 알려준다. 모르는 값은 모름으로 둔다.

아래 key 예시는 승인된 memory claim 사전의 fit, color, material, formality, occasion, activity를 참고했다. 완성된 아이템 feature map 스키마를 새로 확정하는 제안은 아니다. 현 메모리 계약은 선택 이미지·선택 이유·확인된 claim을 표현한다. 아이템 자동 추출 결과의 저장 계약은 후속 설계 대상이다.

B

아이디어 1 · 기억을 먼저 쓰고, 빈틈만 묻기

기본 진입 흐름으로 가장 권한다. 이전에 동의한 취향이 있는 재방문 사용자에게 특히 적합하다. 사용자는 이번 목적만 말하고, 기억이 없으면 빈 프로필로 시작할 수 있다.

  1. 사용자가 “내일 고객 미팅인데 정장처럼 보이기는 싫어”라고 입력한다.
  2. memory layer에서 유효한 “여유 핏 선호·차분한 색 선호”를 가져온다.
  3. 화면에 “여유 핏과 차분한 색을 참고할게요”를 보여준다. 각 조건에 이번 추천에서 빼기와 수정 기능을 둔다.
  4. 추천을 바꿀 공백만 묻는다. “많이 걸으세요?”는 텍스트 버튼으로 답한다.
  5. “단정함”의 경계가 여전히 모호하면 이미지 비교를 제공한다. 이미 명확하면 바로 추천한다.

텍스트 시점: 목적·일정·활동·필수 조건이 없거나 서로 충돌할 때다. 이미 직접 말한 조건에는 반복 확인을 요구하지 않는다.

이미지 시점: “너무 정장 같지 않게”처럼 시각적 정도가 모호하고, 그 차이가 후보를 바꿀 때다. “이 정도 단정함인가요?”라는 질문과 비교 이미지를 보여준다. 사진 업로드는 요구하지 않는다.

기억 활용: 오늘의 예외는 이번 조건으로만 적용한다. 기존 취향은 관련 있고 유효할 때 재사용한다. 과거 요청의 미팅·날씨를 새 요청에 자동으로 가져오지 않는다.

편의성과 주의점

이미 아는 취향을 다시 설명할 필요가 줄어든다. 대신 잘못된 기억을 쉽게 뺄 수 있어야 한다. “이번에 제외”와 “기본 취향 수정”은 서로 다른 조작으로 제공한다.

C

아이디어 2 · 사진에서 원하는 요소를 집기

옷이나 원하는 룩을 이미 가지고 온 사용자의 선택 경로다. 설명을 길게 쓰는 대신 사진을 보여주고, 원하는 부분을 집는다. 사진 없이 시스템의 비교 이미지를 골라도 된다.

  1. 입력창에 선택적인 “사진으로 시작”을 둔다. 기존 기억이나 선택된 레퍼런스를 재사용하면 다시 업로드하지 않는다.
  2. “이 옷으로 코디할래요 / 이런 분위기를 원해요” 중 사용 목적을 고른다.
  3. 시스템은 사진 속 아이템과 눈에 보이는 속성을 후보로 보여준다. 여러 아이템이 있으면 사용자가 대상을 고른다.
  4. 레퍼런스라면 “핏 / 색감 / 디테일 / 전체 분위기 / 직접 설명” 중 원하는 요소를 고른다.
  5. “어디에 입으세요?”처럼 사진으로 알 수 없는 맥락만 텍스트로 보완한다.

사용 화면 예시: 사용자가 사진 속 바지의 핏을 고른다. 이어서 “고객 미팅용으로 코디해 주세요”라고 말한다. 시스템은 선택 대상을 바지로 좁히고, 여유 핏을 이번 조건으로 확인한다. 사진 속 신발·색·소재까지 취향으로 확대하지 않는다.

텍스트 시점: 사진의 용도, 착용 상황, 제외할 요소를 확인할 때다. 사진이 흐리거나 실제 소재가 중요할 때도 텍스트로 보완한다. 사용 목적을 이미 말했으면 다시 묻지 않는다.

이미지 시점: 특정 아이템으로 코디하거나, 말로 설명하기 어려운 룩을 참고하고 싶을 때다. 사용자가 먼저 사진을 주거나 자발적으로 이 경로를 고른다.

기억 활용: 기억한 색·핏은 사진에서 지정하지 않은 부분의 후보를 좁히는 데 쓴다. 사진에 대한 새 의도가 기존 취향과 다르면 이번 요청의 명시 조건을 우선한다. 저장된 취향만으로 원본 사진을 계속 보관하거나 재사용할 수 있다고 가정하지 않는다.

편의성과 주의점

사진 한 장으로 시각적 설명 부담을 줄일 수 있다. 그러나 사진 준비·업로드 자체가 부담일 수 있다. 업로드 없이 진행하는 경로를 유지한다. 사진만으로 몸의 치수·촉감·신축성·취향을 확정하지 않는다.

D

아이디어 3 · 먼저 추천하고, 바꾸고 싶은 부분만 말하기

취향을 미리 설명하기 어렵거나 빨리 결과를 보고 싶은 사용자에게 적합하다. 사용자는 결과를 본 뒤 “무엇을 바꿀지” 말한다. 첫 추천은 대화를 시작하는 시각적 기준점이 된다.

  1. 이번 목적과 명시한 필수 조건을 파악한다. 장기 기억이 있으면 함께 쓴다.
  2. 부드러운 스타일 선호가 일부 비어 있어도 첫 추천을 보여준다. 기억이 없으면 개인화가 제한된 첫 제안이라고 알린다.
  3. 카드에서 “더 편하게 / 덜 격식 있게 / 핏만 변경 / 직접 말하기”처럼 수정 방향을 고른다.
  4. “핏만 더 여유롭게, 색은 좋아요”라는 피드백을 해당 아이템·요소에 연결한다.
  5. 수정한 결과를 보여주고, 새로 확인한 취향 중 이후에도 쓸 항목만 선택적으로 저장한다.

텍스트 시점: 이미지에서 알 수 없는 불편·목적·예외를 말할 때다. “많이 걸어서 이 신발은 싫어요”를 반영하되, 모든 구두를 싫어한다고 일반화하지 않는다.

이미지 시점: 첫 결과를 평가하거나 구체적인 수정 정도를 비교할 때다. 추가 선택은 핏·격식처럼 아직 모호한 요소에만 제공한다. 사용자가 직접 사진을 올릴 필요는 없다.

기억 활용: 다음 요청에는 동의한 수정 사항만 장기로 재사용한다. 클릭·선택·착용을 평소 취향으로 자동 저장하지 않는다. “이 코디는 좋아요”만으로 모든 속성을 선호한다고 확정하지 않는다. “별로예요”처럼 이유가 불명확하면 바꾸고 싶은 아이템·요소를 묻는다.

편의성과 주의점

추천을 보면서 말하면 원하는 차이를 표현하기 쉬울 수 있다. 첫 결과가 크게 빗나가면 수정 부담이 커진다. 중요한 필수 조건의 의미가 불명확하거나 충돌하면 먼저 확인한다. 첫 결과의 부드러운 선호는 비교를 통해 탐색할 수 있다.

E

실제로 언제 무엇을 물을까?

다음 질문은 추천에 미치는 영향, 현재 정보의 불확실성, 사용자의 응답 부담을 함께 보고 고른다. 모델 점수가 높아도 사용자 확인이나 저장 동의를 대신하지 못한다.

지금 상태 다음 상호작용 예시
필수 조건이 모호하거나 충돌함 짧은 텍스트·버튼 질문을 우선 “정장은 필수인가요, 피하고 싶으신가요?”
목적·활동 정보가 후보를 바꿈 텍스트·버튼 질문 “걷는 시간이 많아요 / 적어요”
핏·격식의 시각적 경계가 모호함 시스템이 이미지 비교를 제공 “이 중 어느 정도 여유 핏을 원하세요?”
사용자가 특정 옷·룩을 참고하고 싶음 선택적인 사진과 사용 목적 확인 “이 옷으로 코디 / 이 분위기 참고”
글로 구체적인 조건을 이미 줌 추가 이미지 없이 반영 “검정색, 여유 핏, 재킷 제외”
기억과 현재 입력만으로 추천 가능 질문을 끝내고 추천 사용한 조건과 반영 이유 표시
이미지 준비가 어렵거나 비교를 원하지 않음 텍스트로 전환 “약간 여유 / 넉넉 / 직접 설명”

비교 이미지의 품질도 입력 품질이다. 핏을 물으면 다른 색·무드를 가능한 한 비슷하게 맞춘다. 여러 속성이 함께 달라지면 선택 이유를 추가로 확인한다. 적절한 비교 이미지가 없으면 텍스트로 전환한다.

질문 종료: 필요한 필수 조건의 충돌을 정리했고 추천할 후보가 있으면 진행한다. 영향이 작은 공백은 남겨둘 수 있다. “바로 추천받기”를 항상 제공하고, 미확인 조건이 있으면 그 범위를 알린다. 충족 여부를 모르는 필수 조건은 충족했다고 표시하지 않는다.

F

memory layer는 다음 입력을 어떻게 줄일까?

사용자에게는 “기본 취향 / 이번 조건 / 확인 중”으로 보여준다. 시스템 내부에서는 유효한 장기 기억과 현재 요청의 확인된 조건을 추천에 연결한다.

단계 memory layer의 역할 사용자의 부담을 줄이는 방식
요청 시작 관련 있고 유효한 장기 기억 조회 취향을 처음부터 다시 쓰지 않음
대화 진행 이번 조건·근거·미확인·충돌 구분 이미 답한 내용은 다시 묻지 않음
질문 선택 기억의 공백과 충돌을 전달 대화 정책이 필요한 형식만 제공
추천 표시 반영한 기억과 이번 조건 연결 결과에서 바로 조건 수정
선택적 저장 항목별 내용 확인과 이후 활용 동의 새로 확인한 내용만 검토
다음 요청 동의한 장기만 재사용 지난 요청의 임시 조건을 반복 정리하지 않음

기억한 fit=여유와 이미지 비교에서 선택한 fit=레귤러가 다르면 이번 요청에서만 레귤러를 쓴다. 이 조정만으로 기본 취향을 덮어쓰지 않는다.

가장 중요한 분업

memory layer는 무엇을 알고 있고 무엇이 미확인인지 알려준다. 대화 정책은 어떤 질문을 어떤 형식으로 보여줄지 결정한다. feature map은 아이템의 속성을 표현한다. 추천은 사용자 조건과 아이템 속성을 연결한다.

추천 이후 “다음에도 참고할 요소”를 보여주되 체크 기본값은 해제한다. 명확한 저장 요청이 있으면 대화 중에도 같은 확인·동의 계약을 적용할 수 있다. 반복 선택만으로 자동 장기화하지 않는다.

G

세 아이디어를 연결한 한 번의 사용 예시

다음 내용은 가상 시나리오다. 저장된 기본 취향은 “여유 핏·차분한 색”이다.

  • 1번이 시작을 맡는다. 기억을 먼저 쓰고, 모호한 단정함만 이미지로 묻는다.
  • 2번은 선택 경로다. 사용자가 레퍼런스를 가져왔다면 시스템 비교 대신 그 사진의 특정 요소를 집는다.
  • 3번이 수정을 맡는다. 첫 추천을 본 뒤 신발처럼 필요한 부분만 바꾼다.
