# LUMI System Design — 논문 본문 초안

> 작성일: 2026-10-15 · 검토용 초안. 사용자 제공 파이프라인과 합의한 다섯 부분의 설명 구조를 따른다. 아래 본문은 제안하는 시스템의 동작을 기술하며, 전체 구현 완료나 연구 효과를 보고하는 문서가 아니다. 사례는 가상이다.
>
> 용어 가정: 제공 그림의 `Item Feature Map`을 검색할 아이템의 목표 속성으로 해석하고, 본문에서는 `Target Item Feature Map`으로 표기했다. 실제 상품이 가진 속성은 별도의 상품 속성 표현으로 구분한다. 이 명칭과 구분은 초안 작성을 위한 제안이며, 기존 시스템 설계 정본이나 구현 계약을 변경하지 않는다.

## 1. System Overview: 기억과 상호작용을 통한 패션 선호 구체화

우리는 사용자의 지속적인 취향과 현재 요청의 요구를 함께 활용하는 메모리 기반 패션 추천 시스템 LUMI를 제안한다. LUMI는 사용자의 설명, 이미지 선택, 추천에 대한 수정에서 얻은 근거를 축적하고, 현재 맥락에 맞는 기억을 활용해 원하는 아이템을 찾도록 돕는 것을 목표로 한다. 취향을 처음부터 완전하게 설명하도록 요구하기보다, 이미 알려진 선호와 새로운 피드백을 연결해 현재 원하는 조건을 구체화하도록 설계한다.

그림 1은 LUMI의 전체 흐름을 보여준다. 사용자 입력에서 선호의 의미와 적용 범위를 해석해 후보를 구성하고, 확인한 내용은 세션 기억으로 관리한다. 선택 사실과 그 이유에 대한 잠정 가설은 구분한다. 이후 현재 요청에 관련된 세션 기억과 장기 기억을 조회해 요청별 User Preference Map을 만들고, 이를 아이템의 목표 속성으로 구체화해 상품 검색에 활용한다. 사용자는 추천 이미지의 전체 또는 일부를 선택하거나 텍스트로 요구를 수정할 수 있다. 이 피드백은 현재 세션의 선호 표현과 다음 추천에 반영되며, 이후에도 활용하기로 동의한 내용은 장기 기억으로 축적한다.

예를 들어, 평소 여유로운 핏과 네이비 색상의 바지를 선호하는 사용자가 “이번 발표에는 슬림한 바지를 찾고 싶다”고 요청할 수 있다. LUMI는 이번 요청에서 슬림핏을 적용하면서 네이비 선호를 함께 참고하고, 여유핏이라는 기존 취향은 보존한다. 사용자가 추천된 바지의 이미지를 선택하거나 핏을 수정하면 이번 추천을 조정한다. 다음 요청에서는 이전 발표의 슬림핏 요구를 자동으로 이어받지 않고, 그 요청에 유효한 기억을 다시 조회한다. 이러한 흐름을 통해 세션 안의 추천 수정과 여러 세션에 걸친 취향 축적을 구분한다.

## 2. Memory Formation and Scope: 의미와 적용 범위를 보존하는 기억

LUMI의 기억 단위는 사용자가 표현한 선호나 요구의 의미, 그 근거, 적용 대상과 상황을 함께 다룬다. 예를 들어 “상의는 넉넉한 것이 좋지만 바지는 슬림한 것이 좋다”는 입력은 서로 다른 아이템에 관한 선호로 구분한다. “발표할 때는 슬림한 바지를 입고 싶다”는 요구에는 바지라는 대상과 발표라는 상황을 함께 연결한다. 이 구조는 특정 아이템이나 상황에서 얻은 정보를 사용자 전체의 취향으로 확대하지 않기 위한 것이다.

입력 해석 과정에서는 사용자의 표현을 보존하면서 기억 후보를 구성한다. 상품 속성으로 바로 대응시키기 어려운 의미도 기억의 대상이 된다. 예를 들어 “디자이너적인 요소가 좋다”는 표현은 사용자가 어떤 요소를 지칭하는지 충분히 드러나지 않았더라도 근거와 함께 남길 수 있다. 이후의 선택이나 설명을 통해 의미를 구체화하며, 처음부터 하나의 스타일 라벨로 확정하지 않는다. LLM은 이러한 의미 해석과 선호 후보의 구성을 지원하되, 모델의 추론과 사용자가 확인한 내용을 구분한다.

기억은 적용 범위에 따라 세션 기억과 장기 기억으로 나눈다. 세션 기억은 현재 요청의 요구, 상황, 확인된 선호를 다루고, 아직 확인 중인 선택 이유는 잠정 가설로 구분해 관리한다. 장기 기억은 사용자가 내용을 확인하고 향후 활용에 동의한 선호를 이후의 관련 요청에서도 참고하기 위한 것이다. 표현에 “평소”가 포함되거나 같은 선택이 반복되었다는 사실만으로 장기 저장을 허용하지 않는다. 현재 요청에 내용을 적용하는 것과 이후 요청에서도 활용하는 것은 별도로 결정한다.

이러한 구분에 따라 추천을 위해 구성한 일시적인 속성 해석이 저장된 사용자 의미를 자동으로 변경하지 않는다. 사용자가 입력을 정정하면 해당 대상과 범위의 해석을 수정하고, 장기 기억의 변경에는 변경할 내용과 향후 활용 범위를 다시 확인한다. 의미 해석, 현재 요청의 적용, 장기 활용의 결정을 분리하는 것이 기억 관리의 기본 원칙이다.

## 3. Context-Aware Memory Retrieval: 현재 요청에 유효한 기억의 구성

추천 시점에는 현재 요청의 대상과 상황을 기준으로 활용할 기억을 선택한다. 조회의 목적은 현재 판단에 적용할 수 있는 근거를 구성하는 데 있다. 바지에 관한 선호는 바지를 찾는 요청에서, 특정 상황에 한정된 요구는 해당 상황이 확인된 요청에서 활용한다. 같은 요청 안의 연속 대화는 해당 세션의 근거로 활용하되, 새 요청을 시작하면 앞선 요청 전용 세션 기억은 적용하지 않는다.

관련 기억을 구성할 때에는 현재 요청의 명시적인 요구와 기존 선호의 관계를 함께 검토한다. 같은 대상에 대해 현재 요구가 장기 선호와 충돌하면 현재 요청에서 명시한 조건을 우선 적용하고, 충돌하지 않는 기존 선호는 함께 유지한다. 앞의 사례에서 이번 바지의 핏은 슬림으로 해석하되, 네이비 색상 선호는 계속 참고할 수 있다. 이 과정은 현재 요청에 적용할 근거를 선택하는 것이며, 장기 기억에 저장된 여유핏 선호를 교체하는 것은 아니다.

적용 범위나 의미가 충분히 확인되지 않은 기억은 확정 조건으로 사용하지 않는다. 서로 양립하기 어려운 요구의 우선순위가 불분명하면 사용자에게 필요한 부분을 확인한다. 조회된 기억은 출처와 적용 범위를 유지한 채 다음 단계로 전달되므로, 현재 선호 표현이 어떤 입력과 기억에 근거하는지 구분할 수 있다. 여기서 맥락 기반 조회는 특정 검색 알고리즘의 명칭이 아니라, 기억의 대상·상황·세션 범위를 고려해 활용 근거를 선택하는 원칙을 뜻한다.

## 4. Preference Representation and Item Retrieval: 요청별 선호를 아이템 조건으로 연결

User Preference Map은 조회한 기억과 현재 요청을 바탕으로, 이번 추천에서 무엇을 중요하게 고려해야 하는지 정리한 표현이다. 이 Map은 사용자 전체를 고정적으로 요약한 프로필이 아니라 요청마다 다시 구성하는 내부 표현이다. 각 조건에는 사용자에게서 명시되거나 확인된 내용인지, 맥락에서 잠정적으로 추론한 내용인지, 아직 알 수 없는 내용인지를 구분하고 그 근거를 연결한다. 근거가 부족한 속성을 모두 채우는 것은 이 단계의 목표가 아니다.

앞의 사례에서 User Preference Map은 발표를 위한 바지라는 현재 목적, 이번 요청의 슬림핏 요구, 관련 장기 기억의 네이비 선호를 함께 표현한다. 명시된 핏 요구는 모델의 일반적인 상황 추론보다 우선한다. 발표라는 상황만으로 사용자가 언급하지 않은 소재나 스타일을 필수 조건으로 확정하지 않으며, 필요한 경우 잠정 해석이나 확인할 내용으로 남긴다.

본 초안에서는 그림의 Item Feature Map을 찾으려는 아이템의 목표 속성 표현으로 해석하고, 이를 Target Item Feature Map으로 정의한다. User Preference Map이 현재 사용자의 의도와 그 근거를 다룬다면, Target Item Feature Map은 검색 대상 아이템이 어떤 특성을 가져야 하는지 다룬다. 예를 들어 이번에 찾을 바지의 핏과 색상을 검색 가능한 조건으로 연결하되, 구체적인 속성으로 아직 해석할 수 없는 의미는 보존하고 미정으로 남긴다. 이 두 표현은 정보를 해석하는 논리적 단계를 구분하며, 반드시 서로 다른 모델을 사용한다는 뜻은 아니다.

상품 검색 단계에서는 목표 속성과 실제 상품의 속성 표현을 대조한다. 실제 상품의 속성은 상품 데이터에 근거한 정보이며, 사용자의 선호에서 생성되는 정보와 구분한다. 추천 후보를 구성할 때에는 명시적인 필수 조건과 일반적인 선호, 잠정 추론의 역할을 구별한다. 필수 조건은 후보 적합성을 판단하는 기준으로, 일반적인 선호는 후보 간 우선순위를 판단하는 근거로 활용한다. 충족 가능한 후보가 없거나 중요한 조건을 해석하지 못한 경우에는 이를 확인하고 조건 수정이나 추가 탐색으로 연결한다. 내부 Map은 기본 화면에 노출하지 않고, 사용자는 제시된 아이템과 선택·수정 상호작용으로 결과를 검토하도록 설계한다.

## 5. Feedback and Memory Update: 선택의 해석과 두 범위의 갱신

LUMI는 추천 결과를 다음 상호작용의 대상으로 사용한다. 사용자는 마음에 드는 이미지 전체를 선택하거나 특정 아이템·부분을 가리키고, 텍스트로 원하는 점과 바꿀 점을 설명할 수 있다. 시스템은 선택이 가리키는 대상과 사용자의 표현을 연결해 현재 선호를 구체화한다. 전체 코디에 대한 반응과 그 안의 특정 바지에 대한 반응은 서로 다른 범위의 근거로 다룬다.

이미지 선택은 해당 후보에 대한 긍정적인 근거가 되지만, 그 후보의 모든 속성을 좋아한다는 뜻으로 해석하지 않는다. 시스템은 선택한 이미지의 특성과 사용자 설명을 바탕으로 선택 이유의 가설을 구성할 수 있다. 예를 들어 슬림한 바지를 선택했다면 핏이 이유일 수 있지만, 색상이나 다른 요소가 이유일 가능성도 남겨둔다. 미선택한 후보 역시 곧바로 싫어하는 것으로 기록하지 않는다.

선택 이유의 차이가 다음 추천에 중요하면 짧은 확인 질문이나 이미지 비교를 제공한다. 사용자가 이유를 설명하기 어렵다면 선택 자체의 근거를 유지하고, 확인되지 않은 속성을 확정하지 않은 상태에서 탐색을 이어갈 수 있다. 확인 질문은 모든 선택에 의무적으로 추가하는 단계가 아니라, 해석의 불확실성과 추천에 미치는 영향을 고려해 사용하는 수단이다. 확인된 반응은 해당 대상과 현재 세션에 적용해 User Preference Map과 아이템 목표 조건을 갱신하고 재추천한다.

반복 상호작용에는 두 범위의 갱신이 존재한다. 첫째, 세션 안에서는 선택과 수정으로 이번 추천의 조건을 조정한다. 둘째, 세션을 넘어서는 활용에는 저장할 구체적인 선호를 사용자에게 보여주고 향후 활용 동의를 받는다. 이번에 슬림핏을 선택했다는 사실만으로 평소 여유핏 선호를 교체하지 않는다. 사용자가 지속적인 취향 변화임을 확인하고 이후 활용에 동의한 경우에 해당 기억을 갱신하며, 관련 없는 다른 선호는 유지한다.

사용자는 탐색 중 언제든 원하는 아이템을 확정하거나 중단할 수 있다. 시스템이 추가 탐색이나 종료를 제안하더라도 최종 결정은 사용자에게 둔다. 추천의 확정과 장기 기억 저장은 별개의 선택이며, 저장을 선택하지 않은 피드백은 이후 요청의 장기 선호로 자동 전환하지 않는다.

## 그림 1 캡션 초안

**그림 1. LUMI의 메모리 기반 패션 추천 파이프라인.** 사용자 입력에서 의미와 적용 범위를 해석해 선호 후보를 구성하고, 확인한 내용을 세션 기억으로 관리한다. 시스템은 현재 요청에 관련된 세션·장기 기억을 조회해 User Preference Map을 만들고, 이를 목표 아이템 속성으로 구체화해 실제 상품 검색에 활용한다. 사용자 선택과 수정은 현재 세션의 추천을 갱신하며, 확인한 선호의 장기 활용에는 별도 동의가 필요하다. 실선은 처리·정보 전달을, 점선은 추천 결과에 대한 사용자 피드백을 나타낸다. 그림의 Item Feature Map은 본문에서 Target Item Feature Map으로 정의하며, 실제 상품의 속성 표현과 구분한다.

## 작성자 메모 — 제출 본문에서 제외

이 원고는 사용자가 2026-10-15 제공한 `handsome figure1.pdf`와 [LUMI 시스템 설계 보고서](../../LUMI_system_design.html), [현재 연구 기준](../../docs/master.md)를 바탕으로 작성한 설명 초안이다. 기존 [구현 중심 메모리 원고](system-design-ko.md)는 보존했다. 시스템 설계 정본과 코드·저장 정책·연구 프로토콜을 변경하지 않는다.

최종 원고에서는 Item Feature Map의 의미를 확정하고 그림·본문의 명칭을 맞춰야 한다. 이 초안은 목표 아이템 속성이라는 해석을 사용한다. 실제 상품 속성을 의미하는 경우에는 해당 부분과 그림의 정보 흐름을 함께 수정해야 한다.

부록에는 기억 항목의 전체 스키마, 입력 해석·질문 생성 프롬프트, 조회·충돌 처리의 세부 절차, 상품 속성 목록과 구축 방법, 검색·정렬 설정을 배치할 수 있다. 실제 시스템을 보고하는 최종 논문에서는 본문에도 사용 모델의 역할, 상품 데이터의 출처와 수동·자동 구성 범위, 연구에 사용한 구현과 주요 제한을 짧게 밝혀야 한다. 핵심 기여가 되는 규칙이나 알고리즘은 본문에서 이해할 수 있는 수준으로 설명한다.

기억·속성 조건의 일관성과 실제 아이템에 대한 사용자 선호 판단의 부합은 다른 검증 대상이다. 이 초안은 취향 재현의 정확도, 표현 부담 감소, 반복 사용에 따른 개선을 입증한 것으로 서술하지 않는다. 구체적인 평가 조건과 지표는 연구 설계가 확정된 뒤 별도 평가 절에 기술한다.
