# 0007 · 이미지 선택과 선택 이유의 동시 접수 및 종료 후 장기 동의

- Status: Accepted
- Date: 2026-11-01
- Related Work: FEA→PI 가설 확인이 중심인 대화에서 사용자 이유·맥락을 함께 기억하는 흐름 보완
- Approval: 2026-11-01 (Asia/Seoul), 사용자가 “장기 활용 동의는 해당 대화 세션이 끝날때”, “이미지 선택과 함께 왜 그게 좋은지도 같은 응답으로”, “텍스트는 필수로 잡지는 말자”라고 정하고 문서·구현 반영을 요청함
- Applies to: 로컬 소비자 서비스·HTTP/UI의 비교 응답과 종료 후 확인·장기 활용 동의. 기존 범용 MemoryStore의 장기 생성 호출을 일괄 변경하거나 실제 사용자 DB를 자동 이관하지 않음
- Supersedes: [ADR 0006](0006-fea-to-pi-hypothesis-comparison.md)의 비교 응답 접수 방식 보완. 직접 PI·FEA 가설·PI 중심 상품 비교·별도 장기 동의 원칙 유지

## Context

기존 가설 비교 버튼은 선택을 즉시 반영하고 이유 텍스트는 별도 피드백으로 보냈다. 이 방식에서는 새로운 착용 상황·회피 이유·사용자 표현을 같은 응답의 근거로 다루기 어렵다. 기존 UI는 온보딩이나 최종 상품 미리보기에서도 장기 활용 검토를 노출했다. 사용자는 선택 이유를 선택 사항으로 함께 받고, 장기 활용 동의를 해당 대화 종료 시점에 모으기로 했다.

## Decision

1. **선택과 선택 사항인 이유:** 이미지를 고른 상태는 로컬 초안이다. 사용자는 이유·수정 사항을 적거나 비워 둔 채 같은 반영 버튼으로 전송한다. 텍스트 입력이나 설명을 선택·종료의 필수 조건으로 만들지 않는다. 후보 없음·모르겠음·텍스트만 응답도 유지한다.
2. **동일 근거 묶음:** 이미지 선택과 실제 텍스트를 같은 회차·Feedback·원자적 접수로 저장한다. 선택 사실과 사용자가 말한 이유를 구분하고, 모델이 만든 이유를 사용자 발화로 저장하지 않는다.
3. **확인과 해석의 구분:** 텍스트 없이 명확한 가설 선택만 보내면 기존처럼 표시된 PI 해석만 확인한다. 텍스트가 함께 있으면 수정·상충 가능성까지 함께 해석해 기억 후보를 만든다. 이 경로에서 원래 PI 가설을 즉시 확정하지 않는다. 실제 발화의 상황·회피·취향은 독립 후보로 보존하며 PI/FEA 매핑이 없어도 남긴다. 실패하면 양쪽 근거를 보존한 pending 상태로 같은 피드백을 재처리한다.
4. **종료 후 동의:** 소비자 서비스는 요청이 closed인 종료 요약에서만 future_reuse 검토와 동의 수락을 허용한다. 탐색·온보딩 진행·상품 미리보기·최종 선택만으로 동의가 발생하지 않는다. 항목 선택과 동의 체크는 기본 해제이며 거절·건너뛰기·저장 없이 새 요청을 허용한다.
5. **종료 시 기존 후보 확인:** 종료 전에 이미 접수·해석된 기억 후보는 종료 후 내용·binding을 확인할 수 있다. 종료된 요청에 새 입력이나 늦은 추출 결과를 추가하는 것은 계속 금지한다. 이미지 근거가 있는 후보의 확인에는 당시 후보 묶음·이미지/상품 버전을 재검사한다.
6. **범위 보존:** 장기 활용은 확인하고 동의한 문장·대상·조건만 저장한다. 요청 slot을 자동 제거해 일반 취향으로 넓히지 않는다. 요청 전용 slot 항목은 재사용 목록에서 제외하며, 비교 선택만으로 일반 선호·선택 이유·동의를 추론하지 않는다.

## Alternatives

| 대안 | 판단 |
|---|---|
| 이미지 선택과 이유를 별도 응답으로 접수 | 같은 선택에 대한 이유·맥락의 연결이 약해져 변경 |
| 이유를 필수로 요청 | 설명하기 어려운 사용자의 탐색을 막으므로 채택하지 않음 |
| 설명 유무와 무관하게 PI를 바로 확정 | 텍스트 수정과 충돌할 수 있어 함께 해석하는 경로를 구분 |
| 탐색 중 항목마다 장기 동의 | 사용자가 정한 종료 시점으로 이동 |

## Trade-offs

설명 없이 선택만 보내는 흐름은 유지하면서, 설명이 있을 때는 더 풍부한 기억 근거를 얻는다. 설명이 포함된 응답에는 모델 해석과 후보 확인 단계가 필요하다. 종료 후 후보를 확인할 수 있도록 검토 범위를 넓히지만 원래 요청·근거·카탈로그의 유효성은 계속 검사한다. 추가 이유의 수집량·품질이나 사용자 부담 개선은 아직 측정하지 않았다.

## Consequences

`RespondComparisonUI.text`는 선택 필드이며, 모델·저장 단계는 선택과 텍스트를 함께 받는다. 텍스트가 없으면 기존 비교 확인 경로, 있으면 pending→후보 추출 경로를 사용한다. 소비자 서비스는 열린 요청의 장기 동의 요청·수락을 거부하고, 종료 요약에서 이미 존재하는 후보를 확인·동의하도록 한다. 실행 계약은 [master](../project.md#가설-비교-실행-확장)에 관리한다.

검증은 선택만 제출, 선택+이유 동시 접수, 해석 실패·재시작·재시도 중 중복 방지, 선택과 수정 텍스트의 비확정 처리, 종료 전 동의 거부, 종료 후 기존 후보 확인, 기본 미동의·거절·명시적 동의, 종료 후 늦은 추출 거부를 포함한다. 합성 로컬 검증과 실제 모델 의미 품질·사용자 효과를 구분한다.
