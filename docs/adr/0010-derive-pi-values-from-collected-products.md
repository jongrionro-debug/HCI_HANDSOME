# 0010 · PI value를 수집한 상품 데이터에서 확정한다

- Status: Accepted
- Date: 2026-11-04
- Related Work: 현재 대화의 네이버 쇼핑 상·하의 수집 및 PI value 기준 변경·문서 반영 요청
- Approval: 사용자가 “feature에 대한 value는 크롤링해온 value기반으로 정할거야”라고 정하고 “이부분 변경해놔줘 문서들도 이 맥락에 맞춰서”라고 요청함
- Supersedes: [ADR 0004](0004-adopt-park-2025-feature-map.md)의 PI value를 논문 목록에 고정하는 범위와 [ADR 0008](0008-current-implementation-source-of-truth.md) Decision 1의 해당 JSON을 최종 PI value 정본으로 삼는 범위만 부분 대체

## 맥락

기존 결정은 Park et al. (2025)의 PI 축과 여성 바지 value 목록을 함께 고정했다. 사용자는 네이버 쇼핑에서 상·하의를 수집하고, 실제 상품에 기재된 값을 바탕으로 feature별 value를 정하기로 변경했다. 논문 값과 현재 코드의 바지 전용 실행 한계를 전체 수집 대상의 조건으로 삼으면 새 품목·값을 누락할 수 있다.

## 결정

1. PI의 Type·Brand·Price·Color·Fit·Fabric·Detail 7개 feature 축은 유지한다. 각 value 목록은 수집한 상품 원문과 품목별 분포·누락 확인, 동의어 정규화를 거쳐 확정한다. 수집 전에 최종 value enum을 요구하지 않는다.
2. 원본 속성명·값과 품목·출처를 보존하고 정규화값·변환 근거를 연결한다. 품목별 의미 차이, 소재 원료·혼용률과 원단 구조, 직접 메타데이터·추론값·unknown을 구분한다. 실행 사전은 정리한 수집 결과에 따라 버전으로 확정하며 대화 중 모델이 값을 임의로 추가하는 방식은 채택하지 않는다.
3. 브랜드 목록은 수집 결과에서 정리한다. 가격은 숫자 원값과 통화·판매 조건을 확보한 뒤 구간화 여부·경계를 정한다. 논문의 미공개 브랜드 목록이나 가격 구간 복원은 선행 조건이 아니다.
4. 논문 JSON·CSV의 값·출처·라이선스와 현재 실행 사전은 보존한다. 이 자료는 수집 후 확정할 최종 PI value 사전과 구분한다. 이번 변경은 문서 기준이며 크롤러·새 사전·상의 매핑 구현이나 기존 자료의 자동 변환 완료를 뜻하지 않는다.
5. FEA 30개 태그, 직접 PI와 FEA→PI 가설의 구분, 상품 PI 비교, 내용 확인·장기 활용 동의·삭제 경계, 보고서의 RQ·평가·이미지 선택·메모리 흐름은 유지한다.

## 대안

- 논문 value로 수집 대상을 먼저 제한: 수집한 상·하의 값으로 사전을 정한다는 최신 요구와 맞지 않아 채택하지 않는다.
- 원문 표기를 정규화 없이 실행 value로 사용: 같은 의미의 표기 차이와 품목별 의미를 통제하기 어려워 채택하지 않는다.

## 영향

수집 데이터에 맞는 value를 구성할 수 있지만 최종 목록·정규화 범위·품목별 매핑은 수집 후 정해야 한다. 현재 코드의 고정 사전·Pants 지원·브랜드/가격 제약은 그대로 남아 있다. 후속 실행 연결에서 사전 버전과 기존 자료를 보존하고 registry·상품/목표 Map·모델 입출력·검증을 함께 맞춰야 한다.

현재 방향·실행 상태·남은 범위는 [project.md의 Feature Map](../project.md#feature-map)에서 관리한다. 실제 데이터의 누락·정규화 정확도와 기존 근거·버전·필수 조건 보존을 검증하며, 구조 검사나 합성 테스트를 실제 수집·추천 품질의 근거로 확대하지 않는다.
