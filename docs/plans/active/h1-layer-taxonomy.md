# H1 기본 선호·상황 맥락 레이어 설계 초안

상태: 제안. 아래 택사노미와 값은 시스템 설계를 위한 초안이며, 확정된 명세나 검증된 분류 체계가 아니다. 실제 사용자 값, 이미지·상품 속성 데이터, 추천 규칙은 아직 수집·구현하지 않았다.

## 목적과 출발 자료

대화로 기본 선호를 구체화하면서 현재 상황을 별도로 반영하고, 사용자가 두 정보를 함께 검토·수정하도록 한다. 사용자가 어떤 선호를 유지하고 어떤 조건을 이번에 조정했는지 확인할 수 있어야 한다.

근거 자료는 [시나리오·페르소나](../../../Scenario,Persona.pdf)와 [연구 목표·설문 구성](../../../ResearchObjective,SurveyStructure.pdf)다. 원본의 후드티 제외, 편안함 유지, 발표 후 약속, 장시간 보행 등은 설계 예시로 사용하며 수집된 선호나 추천 성과로 취급하지 않는다.

## 1. 구성 원칙

- **공통 의상 택사노미**: 두 레이어가 같은 색상·핏·아이템 등의 속성과 값 ID를 참조한다.
- **기본 레이어**: 상황을 특정하지 않은 평소의 선호·회피와 중요도를 저장한다. 대화로 수정할 수 있다.
- **맥락 레이어**: 현재 일정·환경·목표와, 이번에 적용할 의상 조건 및 기본 선호의 조정 내용을 저장한다.
- 택사노미에 항목을 미리 정의해도 사용자 값을 모두 채울 필요는 없다. 언급되지 않은 값은 미확인으로 둔다.
- 사용자의 표현은 원문과 함께 보존하고, 기존 값으로 표현하기 어렵다면 자유 표현을 남겨 분류 확장 후보로 삼는다.

## 2. 공통 의상 택사노미 v0.1

표의 후보 값은 초기 예시다. 복수 선택을 허용하며, 복합적인 스타일을 한 범주로 강제하지 않는다. 아이템에 따라 적용할 수 없는 속성은 미확인과 구분한다.

| 상위 항목 | 하위 속성 | 초기 후보 값 | 기록 범위 |
| --- | --- | --- | --- |
| 색상 | 색상군 / 명도 / 채도 | 검정·회색·흰색·베이지·갈색·파랑 등 / 어두움·중간·밝음 / 낮음·중간·높음 | 전체 코디 또는 개별 아이템 |
| 핏 | 몸통 여유 / 하의 여유·형태 | 몸에 붙음·레귤러·여유 있음 / 슬림·스트레이트·와이드 | 상의·하의 등 적용 부위 구분 |
| 디자인 | 패턴 / 로고 / 장식 정도 | 무지·줄무늬·체크·기타 / 없음·작음·두드러짐 / 적음·중간·많음 | 개별 아이템 |
| 아이템 | 상의 / 하의 / 겉옷 / 신발 | 티셔츠·후드티·셔츠·니트 / 데님·슬랙스·스커트 / 오버셔츠·블레이저 / 스니커즈·로퍼 등 | 종류별 선호·회피 |
| 스타일 | 스타일 방향 | 캐주얼·미니멀·클래식·스포티 등 | 전체 코디, 복수 가능 |
| 격식 | 수용하는 격식 범위 | 캐주얼·단정한 캐주얼·세미포멀·포멀 | 전체 코디, 범위로 기록 가능 |
| 착용 요구 | 중요하게 여기는 착용 특성 | 움직임 편함·보행 편함·보온·통기·피부 자극 적음 등 | 사용자 요구로 기록 |

명도·채도·로고 정도처럼 경계가 필요한 값은 이후 이미지 예시와 함께 정의해야 한다. 격식과 단정함도 사용자·상황에 따라 확인할 대상이며, 행사명만으로 정답을 지정하지 않는다. 착용감은 이미지에서 사실로 단정하지 않고 사용자 경험이나 확인 가능한 상품 정보를 구분해 사용한다.

## 3. 기본 레이어에 채우는 값

기록 단위는 사용자 유형이 아니라 **개별 선호 진술**이다. 예를 들어 ‘캐주얼형 사용자’ 하나로 압축하지 않고 아래 선호를 각각 보관한다.

| 속성 | 값 | 선호 방향 | 중요도 예시 |
| --- | --- | --- | --- |
| 색상.명도 | 어두움 | 선호 | 가능하면 유지 |
| 상의.몸통 여유 | 여유 있음 | 선호 | 꼭 유지 |
| 디자인.로고 | 두드러짐 | 회피 | 가능하면 유지 |
| 상의.종류 | 후드티 | 선호 | 조정 가능 |
| 스타일.방향 | 캐주얼 | 선호 | 가능하면 유지 |
| 착용 요구 | 움직임 편함 | 선호 | 꼭 유지 |

위 값과 중요도는 설명용 가상 예시다. 실제 중요도는 사용자가 지정하며, AI가 임의로 필수 조건으로 승격하지 않는다. 기본 레이어의 ‘꼭 유지’도 사용자가 특정 세션에서 예외를 허용할 수 있다.

## 4. 맥락 레이어 택사노미 v0.1

맥락은 **상황 사실**, **사용자 목표**, **이번 적용 조건**을 구분한다. 이 구분은 맥락 레이어 내부 구조다.

| 구분 | 항목 | 채울 값의 형태·예시 |
| --- | --- | --- |
| 상황 사실 | 일정·활동 | 고객 미팅, 발표, 친구 약속 등의 활동 목록 |
| 상황 사실 | 시간·순서 | 내일 오전 미팅 → 오후 복귀, 발표 → 저녁 약속 |
| 상황 사실 | 환경 | 실내·실외, 예상 기온, 비 여부; 입력·확인되지 않으면 미확인 |
| 상황 사실 | 이동·착용 | 보행 적음·많음, 착용 시간, 환복 가능·불가 |
| 사용자 목표 | 원하는 인상 | 단정함, 준비된 느낌, 친근함 등 자유 표현과 후보 값 |
| 사용자 목표 | 피하고 싶은 인상 | 너무 격식 있음, 너무 편한 차림, 과하게 눈에 띔 등 |
| 이번 적용 조건 | 유지할 기본 선호 | 기본 레이어의 개별 선호 ID 참조: 여유 있는 핏·어두운 색 등 |
| 이번 적용 조건 | 조정할 속성·목표 범위 | 격식을 평소보다 높이되 블레이저 수준은 피함 등 |
| 이번 적용 조건 | 추가·제외 | 후드티 제외, 스니커즈 유지 등 공통 의상 값 참조 |
| 이번 적용 조건 | 필수·협의 가능 | 사용자가 정한 필수 조건 또는 조정 가능한 조건 |

복수 일정은 활동별 목표와 조건을 보존하고 환복 가능 여부로 연결한다. 발표와 저녁 약속을 하나의 행사명으로 합치거나 모든 일정에 동일한 격식을 요구하지 않는다.

## 5. 선호·조건과 함께 저장할 정보

| 필드 | 용도 |
| --- | --- |
| ID, 대상, 속성, 값 | 무엇에 관한 진술인지 식별; 예: 상의·종류·후드티 |
| 선호 방향·조건 연산 | 기본: 선호·회피·상관없음 / 맥락: 유지·완화·범위 지정·추가·제외 |
| 중요도 | 꼭 유지·가능하면 유지·조정 가능·미확인; 맥락 조건은 필수·협의 가능·미확인 |
| 적용 범위 | 기본 또는 특정 세션·활동; 세션 시작·종료 시점 포함 |
| 근거 | 사용자 발화, 이미지 선택, 선택 이유 등의 원본 참조 |
| 확인 상태 | 사용자 명시·AI 해석 미확인·사용자 확인·사용자 수정 |
| 변경 이력 | 이전 값과 수정 이유를 보존하여 수정·되돌리기 지원 |

미확인, 명시적으로 상관없음, 해당 없음은 서로 다른 상태다. 예를 들어 색상을 말하지 않았다고 모든 색상을 수용한다고 해석하지 않는다. 이미지 선택만으로 이미지의 모든 속성을 선호 값으로 채우지 않는다.

프로필 KG에서는 `사용자 → 선호 진술 → 속성·값`과 `선호 진술 → 근거`를 연결할 수 있다. 맥락 레이어는 `세션 → 활동·목표·조건`, `세션 조건 → 참조하는 기본 선호`를 연결한다. 동일한 후드티 값에 기본 선호와 세션 제외 조건이 함께 존재할 수 있다. 구체적인 직렬화·DB 계약은 이후 확정한다.

## 6. 두 레이어를 조정하는 예시

사용자 발화: “내일 고객 미팅이라 후드티는 빼고 싶어요. 그래도 편하고 너무 정장 같지는 않았으면 해요.”

| 항목 | 기본 레이어 | 이번 맥락 | 현재 적용 |
| --- | --- | --- | --- |
| 상의 종류 | 후드티 선호 | 후드티 제외 | 이번에는 후드티 제외 |
| 핏 | 여유 있는 핏 선호 | 편안함 유지 | 여유 있는 핏 유지; 실제 착용감은 별도 확인 |
| 색상 | 어두운 색 선호 | 별도 변경 없음 | 어두운 색 선호 유지 |
| 격식 | 캐주얼 선호 | 평소보다 단정하게, 정장 느낌 회피 | 허용 범위를 대화·예시로 확인 |

‘고객 미팅’이라는 사실만으로 블레이저를 필수로 정하지 않는다. 또한 ‘편하다’는 표현을 기존 핏 선호를 참조하는 해석으로 제시할 수 있지만, 보행 편안함이나 소재 감각을 뜻하는지 필요에 따라 확인한다.

조정 규칙 초안:

1. 범위가 모호하면 ‘평소에도 / 이번만’ 중 어느 뜻인지 확인한다. 확인 전에는 기본 프로필에 확정 반영하지 않는다.
2. 세션에서 명시한 조건을 해당 세션에 적용하고, 조정되지 않은 기본 선호를 함께 참조한다.
3. 조건끼리 충돌하거나 후보가 없으면 사용자에게 유지·완화할 조건을 선택하게 한다. 필수 조건을 조용히 무시하지 않는다.
4. 일회성 선택은 기본 선호를 덮어쓰지 않는다. 반복 선택은 재확인할 근거이며, 자동 승격의 근거로 삼지 않는다.
5. 세션 종료 후 맥락 조건의 적용을 끝낸다. 이후에도 반영할지는 사용자가 ‘평소 선호로 저장’ 또는 ‘비슷한 상황에서만 적용’을 구분해 확인한다. 후자의 조건부 저장 계약은 별도 설계가 필요하다.

## 7. 사용자 검토와 H1 관찰

검토 화면은 ‘평소의 나’와 ‘이번 상황’을 나란히 보여주고, 각 진술의 값·중요도·적용 범위를 수정하게 한다. 조정된 항목은 원래 선호와 이번 적용 내용을 함께 보여준다. 전체 택사노미를 긴 설문으로 먼저 채우게 하기보다 현재 선택에 필요한 미확인 항목부터 질문한다.

H1의 비교 조건에서는 동일한 의상 속성과 후보를 사용하고, 레이어 구분·검토·수정 방식의 차이를 중심으로 설계한다. 택사노미를 채운 개수만으로 H1 성과를 판정하지 않는다. 자기다움, 상황 적합성, 통제감과 함께 적용 범위 수정·조건 조정 행동을 관찰하는 방안을 검토한다. 비교 조건, 측정 문항과 분석 방식은 아직 미정이다.

다음 확정 작업은 두 원본 시나리오를 위 항목으로 표현해 누락·중복을 점검하고, 소수의 대화 예시에서 사용자 표현을 강제로 축약하지 않는지 확인하는 것이다. 이미지·상품 후보에 같은 속성 체계를 적용할 수 있는지도 별도로 확인해야 한다.
