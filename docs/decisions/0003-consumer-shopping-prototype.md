# 0003 · 소비자용 쇼핑 메모리와 목표 feature 프로토타입

- Status: Accepted
- Date: 2026-10-14
- Related Issue: [#2](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/2)
- Approval: 사용자가 현재 채팅에서 기획 기반 구현을 전부 위임하고 LLM 연결까지 진행하며 스키마/feature를 일반 쇼핑에 맞게 줄여도 된다고 명시했다. 연결 방식 확인에서는 **“연결 코드와 테스트까지 만들고 실제 호출은 나중에”**를 선택했다.
- Related Decisions: [0001](0001-memory-boundaries.md), [0002](0002-memory-prototype-storage.md)

## Context

승인된 v0.2는 기억·근거·명령·조회·삭제 설계와 가상 검증 자료다. 실제 앱·DB는 없었다. 후속 [목표 feature 계획](../../archive/docs/target-feature-inference-plan.md)은 item65/outfit9와 새로운 projection을 제안했으나 일반 쇼핑에서 모든 디자인 속성을 입력/추론할 필요는 없다. 사용자는 계획을 승인하고 축소·구현·Issue/PR 작업을 위임했다.

## Decision

1. Python 3.11+·SQLite·표준 라이브러리로 로컬 프로토타입을 구현한다. 실행 계약의 정본은 [현재 동작 문서](../shopping-memory-prototype.md)와 `src/stylemate_memory/`이며, 역사적 v0.2 JSON Schema와 같은 wire format이라고 주장하지 않는다. v0.2의 확인/동의·범위·현재 예외·소유권·원자성·보관 원칙은 유지한다.
2. 소비자용 17개 feature를 Python registry 한 곳에서 정의한다. 기본 카테고리는 아이템 종류에서 파생하고, 기장은 대상별로 통합하며, 로고는 없음/크기로 축약한다. 섬유 혼용률·제품 ID·코디 전체 조합·세부 봉제/디테일은 이번 실행 계약에서 제외한다. 전체 PDF와의 대응/축약은 registry metadata에 남긴다.
3. 기억은 내용, feature/values, 선호·회피·필수, 강도, any/all/range, 대상 selector, 상황 조건, 유효 기간과 확인/동의 참조를 보존한다. 대상별로 조회한 뒤 충돌을 판정한다. 의미를 바꾸는 replace는 새 ID이며 promote는 확인된 단기 원본을 유지하고 새 장기 ID를 만든다.
4. API의 `user_id`, 확인/동의/evidence 참조, 상황 facts는 신뢰된 로컬 호출자가 제공한다. 이 프로토타입은 실제 로그인·입력 진위·이미지 이해·자동 자연어 메모리 생성 UI를 구현하지 않는다. 모델은 이 쓰기 API에 접근할 수 없다.
5. 모델은 inferred soft 목표와 짧은 질문만 제안한다. 직접 binding은 시스템이 보존하고, 값·대상·부정/필수·근거·충돌·현재성을 검증한 뒤 프로필을 조립한다. 결과를 자동 저장하지 않는다. 미정·비적용·상충 상태를 구분한다.
6. 외부 연결은 OpenAI Responses API adapter와 주입 가능한 HTTP transport로 구현한다. 모델은 호출자가 지정하고 키는 명시적 향후 openai 명령에서만 환경 설정으로 읽는다. 기본 demo/rule 추론과 모든 이번 검증은 오프라인이며 실제 API 키·모델 호출은 하지 않는다. structured output, `store=false`, timeout·응답 거부/불완전/오류 처리를 검증한다. 이 flag가 사업자 전체 로그/보관의 제거를 보장한다고 해석하지 않는다.
7. DB에는 전체 대화/이미지/모델 응답을 별도 저장하지 않는다. 항목의 최소 내용·근거 참조와 내용 없는 이벤트/멱등 결과를 관리한다. 실제 삭제는 관리 DB 행·관련 근거/영수증·journal·정리를 포함하고 재시도 경계를 보존한다. 저장매체·OS/사용자 백업의 복구 불가를 주장하지 않는다.
8. 이번 범위는 기존 브랜치의 구현·검증·Issue #2·PR까지다. 기존 사용자 AGENTS 변경과 설명 영상/HTML을 자동 포함하지 않으며, 승인된 설계 자료 중 실행/문서 의존성만 검토해 포함한다. main 병합·배포·연구 데이터 수집은 하지 않는다.

삭제 재시도는 내용 없는 삭제 명령 fingerprint와 opaque nonce/tombstone을 24시간 유지하는 경계로 축소한다. 과거 content/일반 생성 payload digest·삭제 항목 ID는 남기지 않고, 24시간 이후 ID 재사용을 허용한다. 구버전의 원문/요약·별도 벡터/디스크 캐시를 도입하지 않으며 현재 context에는 실제 살아 있는 source만 허용한다. 영구 멱등성·과거 원문의 의미 재유입 탐지는 주장하지 않는다.

## Alternatives

| 대안 | 검토 결과 |
|---|---|
| item65/outfit9를 모두 구현 | 제품 디자인/추출에 유용하지만 일반 쇼핑 맥락에서 불필요한 미정 값·연산이 늘어남. 원본은 설계 참조로 보존 |
| 자연어 기억을 매번 그대로 모두 전달 | 요청 경계·부정·현재 예외·삭제/기간을 기계적으로 검증하기 어려움 |
| 모델이 메모리와 목표값을 함께 갱신 | 모델 추정이 장기 취향/사용자 동의로 바뀔 위험. 읽기 전용 제안 경계를 채택 |
| SDK·웹 프레임워크·공개 API 도입 | 현 단계에 인증·서버·운영 의존성이 필요하지 않음. stdlib transport+CLI로 연결을 검증 |
| 기본 provider를 실제 OpenAI로 설정 | 사용자가 실제 호출은 나중으로 정했으므로 rule 기본값과 명시적 openai 설정을 선택 |

## Trade-offs

표현 가능한 상세 디자인 조건이 줄어든다. 17개 속성의 한국어 표시 이름은 제공하지만 제품 화면은 없다. 사용자가 모든 칸을 채울 필요는 없고 확인된 상황과 관련 속성만 사용한다. LLM의 자연어 해석 품질은 가상 응답 테스트로 증명할 수 없으며 실제 모델 평가가 남는다.

로컬 호출자를 신뢰하는 경계는 공개 서버 인증을 대신하지 않는다. 공급자가 반환한 허용된 JSON도 의미적으로 올바른 목표인지 사람의 검토가 필요하다. 관리 DB 삭제 검증은 외부 백업·SSD 포렌식 소거와 구분한다.

## Consequences

역사적 설계·연구 기준을 보존하면서 작은 실행 계약과 테스트를 도입한다. 향후 feature 확대·자연어 입력/이미지 처리·제품 UI·인증·실제 모델 호출은 이 프로토타입의 확인/동의/현재성 경계를 유지해 확장한다. 실행 명령·지원 범위·검증 결과와 미실행 범위는 [현재 동작 문서](../shopping-memory-prototype.md)와 PR에 기록한다.
