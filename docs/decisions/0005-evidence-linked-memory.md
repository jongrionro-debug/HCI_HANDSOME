# 0005 · 근거와 해석을 분리하는 장단기 메모리

- Status: Accepted
- Date: 2026-10-29
- Related Work: 메모리 선행연구·이미지/텍스트 방향·저장 형식 검토 후 [실행용 프롬프트](../../output/lumi-implementation-session-prompts.txt)의 공통 규칙 및 TASK A0 실행 요청
- Approval: 2026-10-29 (Asia/Seoul), 사용자가 “output/lumi-implementation-session-prompts.txt를 읽고 공통 규칙과 TASK A0의 프롬프트만 실행해. 다른 TASK는 실행하지 마.”라고 요청했다. A0의 채택 조항에 따라 master의 lumi-memory-v1과 이 제안을 아래 제한의 1차 로컬 구현 기준으로 승인했다. 날짜는 실제 A0 실행일이며 프롬프트 작성일을 승인일로 전용하지 않았다. 후속 TASK 실행을 자동 승인한 것은 아님
- Applies to: 기존 Python·SQLite·로컬 HTTP, 별도 소비자 HTML/CSS/JavaScript, 표준 로컬 상품 가져오기, 교체 가능한 모델 adapter의 실험용 구현 기준. A0는 공통 인터페이스만 정의하며 v1 저장·모델·검색·UI 및 DB 이관은 미연결
- Supersedes: 없음. ADR 0001/0002의 기존 프로토타입 확인·동의·저장·삭제 경계와 ADR 0004의 확정 사전은 유지

## Context

보고서는 모호한 취향의 표현/맥락을 보존하고 발화·선택 사실과 시스템 추론을 구분하며 관련 기억에서 목표 Feature Map을 만들도록 한다. 현재 `MemoryStore._validate_memory_payload()`는 지원 feature/fact와 values를 요구하고 추출기는 사전 밖 표현을 `unmapped`로 반환한다. 전체 대화·후보 해석은 프로세스 메모리에만 있어 재시작 후 복원되지 않는다. 확인·동의·요청 격리 기반을 유지하며 표현과 근거 연결을 넓혀야 한다.

선행연구의 구조화 기억·복합 검색·학습형 관리 정책은 설계 참고이며 사용자의 확인·이후 활용 동의를 대신하지 않는다. 적용할 연구 관점은 [master의 선행연구 표](../master.md#선행연구에서-가져오는-범위)에 둔다.

## Decision

아래를 1차 로컬 구현 기준으로 채택한다. 필드 역할·입력/조회 흐름·스택의 정본은 [핵심 설계안](../master.md#장단기-메모리-핵심-설계안), 구체 필드·상태·예제 payload는 [저장·입출력 계약 v1](../master.md#저장입출력-계약-v1), 함수/모듈 소유권은 [A0 공통 인터페이스](../master.md#a0-공통-인터페이스와-담당-경계)와 [contracts.py](../../src/stylemate_memory/contracts.py), 구현 순서·완료 조건은 [다음 작업](../master.md#다음-작업)에 둔다. 계약 채택은 실행 연결·DB 이관 완료를 뜻하지 않는다.

1. 장단기 scope와 내용의 종류를 분리한다. 입력·선택 근거, 독립 기억 문장, 시스템 가설, 현재 요청 상태를 구분해 최소 원문·대상·조건·시각·확인/동의와 연결한다. 요약·반복 선택을 자동 장기화 규칙으로 두지 않는다.
2. 자연어 기억과 근거를 정본으로 보존하고 사전 매핑은 선택적으로 둔다. 문장 확인과 PI/FEA 값 확인을 구분한다. 목표 Feature Map은 조회 뒤 생성하는 결과이며 새 사용자 근거로 재저장하지 않는다. ADR 0004의 사전·미정 범위는 유지한다.
3. Python·SQLite와 기존 `apply_batch()`의 원자성·멱등·버전 검증을 확장한다. 관계는 같은 SQLite에서 표현한다. 모델은 후보·해석·질문을 제안하고 권한·확인·동의·실제 상태 전이는 코드가 검증한다. 인증·공개 API·제품 전체 스택은 이 제안 범위가 아니다.
4. 유효성/범위 필터와 직접 조건 확보 뒤 구조·키워드·의미 검색을 결합한다. 충돌과 필수 조건 보존은 점수보다 우선한다. 초기 순위·근거 묶음은 결정적으로 구성하고 강화학습 관리자·LLM 재순위 모델은 도입하지 않는다. 임베딩 모델/의존성·조회 예산은 합성 한국어 사례 비교 후 선택한다.
5. 요약·색인·임베딩은 원본 ID/버전에서 재생성하는 파생 자료다. 원본의 동의·scope·기한을 상속하며 변경·철회/삭제를 전파한다. 요청 삭제와 독립 동의한 장기 항목 삭제를 구분하고 과거 요약/모델 출력에서 삭제한 내용을 재생성하지 않는다.
6. 기존 보관 기간·동의 분리·삭제·외부 호출 경계와 보고서의 RQ·과제·평가 계획은 바꾸지 않는다. 실제 모델/상품 검색·실데이터 이관·사용자 연구는 문서 작성으로 실행하거나 검증한 것으로 보지 않는다.
7. 소비자 서버는 로컬 단일 테스터로 두고 trusted user_id·DB/상품/이미지 경로를 서버 설정에서 공급한다. UI가 보낸 임의 사용자 ID·파일 경로·snapshot이나 모델 bool은 확인/동의 이벤트가 아니다. 서비스가 서버 표시 snapshot을 B의 저장 경계에 연결하고 목적별 이벤트를 발행한다. 내용 확인·binding 확인·future_reuse·최종 선택·탐색 종료는 별도 전이다.
8. 모델 기본 실행은 fake이며, 명시적 OpenAI Responses 설정의 기본 모델 후보는 gpt-6-luna로 두고 설정으로 교체 가능하게 한다. 실제 API 호출·키 설정/접근·Codex 로그인 의존 실행은 이번 승인 범위가 아니다. API wire 형식 확인·fake transport 검증은 C1에서 하고 실제 계정 접근권한/의미 품질은 별도 검증한다. provider 자동 fallback을 하지 않는다.
9. 상품은 표준 JSON/JSONL CatalogRecord로 공급하고 원자료·제공 라벨·검증 라벨·모델 해석·미확인을 구분한다. D가 공급하는 raw/map/image/catalog 버전을 A/B가 후보 전체와 대조한다. 사진/FEA 요구만으로 실제 성능을 확정하지 않는다. 크롤러·외부 이미지 수집·외부 저장 서비스·공개 인증/배포·최종 제품 스택 확정은 범위 밖이다.

## Alternatives

| 대안 | 판단 |
|---|---|
| 기억을 PI/FEA 값으로만 저장 | 모호한 표현·선택 맥락·미확인 이유를 잃고 사전 재해석이 어려움 |
| 단기 전체를 요약해 자동 장기화 | 일회성 요구와 지속 취향·관찰과 추론·확인과 이후 활용 동의가 섞임 |
| 전체 대화를 장기 정본으로 보관 | 잡음과 최소 보관·항목별 삭제 부담이 늘어남. 필요한 구절과 독립 동의 snapshot을 선택 |
| 외부 메모리 제품·벡터/그래프 DB를 정본으로 사용 | 운영·동의/삭제 전파 경계가 늘어남. 현재 규모에서는 SQLite와 교체 가능한 검색 adapter로 먼저 검증 |
| 강화학습 기반 자율 관리자 | 학습 데이터·보상·재현 비용이 필요하며 LUMI의 동의·정책을 보장하지 않음 |
| 근거 연결형 자연어 항목 + 기존 정책 경계 | 로컬 구현 기준으로 채택. 검색 품질·파생 자료 삭제는 추가 검증 필요 |

## Trade-offs

표현 보존과 사전 해석을 분리하면 나중에 의미를 구체화하고 어떤 기억이 목표를 바꿨는지 설명하기 쉽다. 대신 근거·항목·가설·매핑 버전과 파생 관계를 관리해야 한다. 문장 보존이 해석 정확성을 보장하지 않으므로 미정과 필요한 확인을 유지한다.

SQLite 정본은 현재 로컬 구조를 유지하지만 한국어 검색 품질을 보장하지 않는다. 의미 검색에는 호출/색인 비용·재색인·삭제 검증이 추가된다. 모델과 수치 예산을 정하기 전 하이브리드 검색 구현이 완료됐다고 주장하지 않는다.

가설을 별도 테이블로 복제하는 대신 MemoryItem의 원래 출처·확인·수명 상태로 구분하면 전이와 삭제 경계가 단순해지지만 조회에서 엄격한 상태 필터가 필요하다. PI의 속성값 배열과 FEA의 요구 태그 방향을 분리하면 다형 출력 검증이 필요하지만 사용자 요구와 상품 성능을 같은 값으로 오인하는 위험을 줄인다. 모델별 원본 출력이나 전체 채팅을 정본으로 저장하는 대안은 채택하지 않는다.

## Consequences

저장 표현·근거와 합성 DB 이관 → 추출/확인 → 조회/목표 → 검색 비교·삭제 전파 순서로 검증한 뒤 이미지·상품·소비자 UI를 연결한다. 기존 승인 ADR 본문·원본 PDF·보관 자료는 수정하지 않는다.

기존 17개 사전과 새 PI/FEA의 의미를 자동 치환하지 않는다. 동일한 의미·대상·조건·기간 안에서만 기존 확인/동의를 유지하고 범위가 넓어지면 새 확인/동의를 받는다. 실제 사용자 DB·자격 증명에 접근하지 않고 합성 자료로 이관·rollback부터 확인한다.

기존 consumer-17-v1 호출은 유지하고 명시적인 lumi-memory-v1 요청/함수/설정으로 단계적으로 연결한다. 없는 인용은 재구성하지 않고 원래 항목과 근거 누락·매핑 미정 상태를 legacy 표현으로 보존한다. A0는 공통 타입·Protocol·참조/fingerprint 검사와 기존 문서 원문 연결만 복구한다. 사전·저장·추출·조회·상품·UI 구현은 각 후속 TASK의 별도 실행에서 완료 조건을 검증해야 한다.

자유 표현 보존·동일 요청 재개/새 요청 격리·선택 사실/가설 분리·장기 동의·현재 예외/충돌·근거 완전성·늦은 응답·철회/삭제/재색인·배치 실패를 검증한다. 기존 테스트/가상 데모를 재사용하고 새 위험에만 테스트를 추가하며, 모델 의미 품질·사용자 연구 효과와 구분한다.
