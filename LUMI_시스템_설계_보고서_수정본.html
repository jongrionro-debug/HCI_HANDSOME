초기 사용자 선호 분석 및 후보 생성

① 초기 선호 해석 LLM

Explicit 현재 요청에 명시된 조건
Long-term 동의를 받아 저장된 평소 취향
Context-derived 계절·상황 기반 잠정 추론
Hypothesis 근거가 약한 선호 가설

② Feature Map 운용 Policy

확실하지 않은 사용자 선호는 Unknown 가능.
모든 속성을 사용자 취향으로 채울 필요 없음.
후보에 필요한 값은 코디 설계 + 실제 상품 검색으로 구체화.

후보전략의도
LOOK A · B장기기억 기반 ×2평소 선호를 충실히 반영하되 두 코디 사이에도 다양성 확보
LOOK C인접 스타일 ×1기존 취향에서 자연스럽게 확장
LOOK D · E새로운 스타일 ×2숨은 취향·이번 요청의 다른 선호 탐색

우선순위: 현재 요청의 명시적 제약 > 이번 세션에서 확인된 선호 > 관련 장기기억 > LLM 가설. 2:1:2는 초기 기본 전략이며, 현재 요청과 충돌하면 조정한다.

사용자 인터랙션과 선호 업데이트

3

Image-first 기반 사용자 피드백

초기 LOOK 5개를 제시하고 사용자가 마음에 드는 후보를 0~5개 복수 선택한다. 전체 룩의 상의·하의 등 이미지 부분 선택도 허용한다.

1개 선택

선택 룩을 긍정적 증거로 기록. 특정 속성 선호는 아직 가설.

복수 선택

선택 룩의 공통·차이 및 미선택 후보와의 차이를 분석.

0개 선택

전부 불만족. 이유를 짧게 확인하거나 다른 방향으로 재탐색.

※ 미선택 ≠ 싫어함. 부분 선택은 상의·하의 등 Item-level 근거, 전체 룩 선택은 Outfit-level 근거로 분리한다.

4

Adaptive Feedback & Questioning

LLM이 선택·미선택 LOOK의 Feature와 부분 선택 근거를 분석해 선택 이유의 가설을 만든다. 설명이 충분하면 질문 없이 잠정 가설로 재추천하고, 확인이 유용할 때만 LLM이 구체적인 이유를 먼저 제안한다.

선택 이유가 불확실할 때 · LLM의 가설 확인
“두 코디 모두 여유로운 핏이네요. 이런 핏이 마음에 드셨나요?”
맞아요다른 부분이 좋아요잘 모르겠어요

‘다른 부분’ 선택 시 → [상의] [하의] [색감] [전체 조합] 등 보조 칩

기존 선호와 충돌할 때 · 이번 세션만 확인
“이번에는 Oversized 기반으로 추천할까요?”
이번엔 Oversized평소대로둘 다직접 입력
사용자 반응 / 상태Agent의 처리
LLM의 추론으로 충분질문 생략 → Hypothesis로만 반영해 재추천 (확정 금지)
“맞아요” / “다른 부분”가설 확인 → 세션 선호 갱신 / 보조 선택지로 이유 좁히기
“잘 모르겠어요”
“그냥 느낌이 좋아요”		이유 질문 중단. 선택 LOOK 선호는 유지; 유용할 때만 이미지 비교, 아니면 유사 코디 재추천
장기기억과 충돌텍스트 원탭으로 현재 요청에 적용할 선호 확인; 장기기억 보존

이미지 비교는 선택적 Fallback: 말로 이유를 설명하기 어렵고, 해당 속성 구분이 추천에 중요하며, 비교 가능한 후보가 있을 때만 2~3개 제시한다.

5

Preference Update & Re-recommendation

Evidence 기록(LOOK·부분 선택·원탭) → Session Preference 갱신(Confirmed / Hypothesis 구분) → 재추천 또는 종료 제안. 기존 장기기억과의 일시적 불일치는 세션에서만 우선 적용한다.

사용자가 언제든 종료 최종 결정권

[이 코디로 확정] [여기서 종료]를 상시 제공. Agent 판단과 무관하게 사용자가 확정·중단할 수 있다.

Agent는 종료를 제안 Hybrid

긍정적 반응 + 필수 제약 충족 + 추가 개선 여지 감소 시 [확정] [더 탐색] 제안. 반복 불만족·피로 신호에는 [방향 전환] [조건 수정] [종료] 제공.

세션 종료 ≠ 장기기억 변경 · 종료 후에는 선택적으로, 저장할 구체적 선호를 사용자에게 보여주고 향후 활용 동의를 별도로 확인한다. 자동 저장·교체 금지.

Agent Architecture

컴포넌트주요 책임

Rule-based Policy명시적 조건 우선, Feature 값 검증, 기억 충돌·상태 갱신, 질문 예산·비교 조건 및 사용자 종료권 보장
Recommendation EngineProduct Feature DB 검색, 실제 상품 기반 코디 구성, 다양성·연관성 반영, 후보 재정렬
Memory Layer장기/세션기억 분리, 근거·적용 범위 검증, 종료 후 장기기억 후보에 대한 별도 동의 관리

설계 원칙: LLM은 의미를 추론하고, 정책은 무근거 확정·기억 오염을 막는다. 각 컴포넌트는 논리적 역할이며 반드시 별도의 LLM Agent일 필요는 없다.
