# ③ 언제 어떤 방식 (상황 매핑)

- 주인: 파트 3 담당 (Issue [#28](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/28), 사건 기반 질문 [#30](https://github.com/jongrionro-debug/HCI_HANDSOME/issues/30))
- 상태: **v1 초안** (2026-11-28, 확인 지점 A 리뷰용). 코드에서는 [graph/questions.py](../../src/stylemate_memory/graph/questions.py)의 `candidates`·`should_ask`·`choose`가 이 문서를 구현한다. 지금 코드는 v0(축별 기본 방식 표 `DEFAULT_MODE`, `ASK_GAP` 2턴)이다.
- 방식 이름은 [1-modes.md](1-modes.md) v1 초안(PR #31)의 코드 이름을 쓴다. 답 반영과 진행 신호는 [2-feedback.md](2-feedback.md) v1 초안(PR #32)을 따른다.
- 판단 구조는 경호의 질문 매핑 A안(규칙 주도)·B안(LLM 주도) 비교에서 **B안을 에이전트 호출 1회에 합친 형태**로 정했다([agent-pipeline.md](../../docs/specs/agent-pipeline.md)의 `ask_question`).
- 근거 칸에는 카드 ID를 적고, 근거가 없으면 `가정`이라고 적는다. 수치는 모두 `가정`이며 파일럿에서 정한다.

## 1. 결정 구조

**코드 규칙은 "지금 쓸 수 있는 방식"과 기본값을 정하고, LLM은 그 안에서 고른다.** 규칙의 결정은 항상 같이 계산해 로그에 남긴다(그림자).

| 단계 | 주체 | 하는 일 |
|---|---|---|
| ① 울타리 | 규칙 | 다른 안내가 떠 있으면 묻지 않는다. 글 고정 상황(3절)은 글로만 묻는다. 간격·개수 규칙(5절)을 지킨다 |
| ② 트리거 → 허용 목록 | 규칙 | 이번 턴 상황(방금 고른 것, 사용자 말, 빈칸)을 보고 방식별 조건(2절)을 만족하는 것만 허용 목록에 넣는다. 보여 줄 상품이 없는 방식은 빠진다 |
| ③ 선택 | LLM (에이전트 1회 호출의 `ask_question`) | 허용 목록에서 축·방식 하나를 고르거나 이번엔 묻지 않는다. 근거 신호(8절 어휘)와 질문 문구를 함께 낸다 |
| ④ 검증·대체 | 규칙 | 목록 밖이거나 근거 신호가 입력 사실과 다르면 버리고 규칙 기본값(4절)을 쓴다 |

질문은 두 종류다.

- **반응형**: 사용자가 방금 한 행동 때문에 묻는다. 바로 묻지 않으면 신호가 사라진다.
- **선제형**: 빈칸을 채우려고 먼저 묻는다.

## 2. 방식별로 언제 나오나

| # | 방식 | 종류 | 언제 허용되나 (규칙) | LLM이 판단할 것 | 근거 |
|---|---|---|---|---|---|
| 4 | 공통점 칩 `reason_chips` | 반응형 | 직전에 2장 이상 골랐고, 고른 상품끼리 겹치는 값이 2개 이상 | 지금 물을지. 이유를 글로 이미 말했으면 생략 | McCarthy et al. 2005 (dynamic critiquing), `가정` |
| 3 | 단어 정렬 `explain_images` | 반응형 | 사용자가 쓴 단어의 PI 가설 후보가 **한 축 안에서 2개 이상**이고, 값이 모두 사전 안이며, 값마다 대표 이미지가 있음 (예: "깔끔한" → Style 두 값) | 어떤 단어를 확인할지 | Kovashka & Grauman 2015, `가정` |
| 5 | 기준 이미지 조정 `relative_adjust` (칩 + 입력창) | 반응형 | 6절 트리거 중 하나 + 순서형 축(Fit·Tone·Length·Weight)에 빈칸 | 칩으로 보여 줄 축 2~3개 | Kovashka et al. 2012 (WhittleSearch), `가정` |
| 6 | 사진 붙은 선택지 `photo_chips`(가칭) | 선제형 | 묻는 축이 사진 방식 축이고(7절), 1번 이미지를 뽑을 수 없을 때(초반, 7절), 또는 "용어 모름" 신호가 있을 때. 값마다 대표 이미지, 선택지 최대 4개 | 다중 선택 허용 여부 (Type·Style·Pattern·Detail은 다중, 순서형 축은 단일) | Yuan et al. 2024, `가정` |
| 1 | 이미지 여러 장 `select_images` | 선제형 (반응형 대체로도) | 묻는 축이 사진 방식 축이고, 그 축 값만 다르고 나머지 확인된 PI가 같은 상품을 **2~4장** 뽑을 수 있을 때(후반, 7절). 2장이면 대조 2장 화면 | "모르겠어요", "보여 줘"면 고름 | `joachims2005-relative-preference`, `bollen2010-choice-overload` |
| 2 | 자연어 질문 `text_options` + 입력창 | 선제형, 글 고정, 마지막 대체 | 항상 허용. 글 고정 상황에서는 이것만 허용 | 말로 정하기 쉬운 축이거나 사용자가 말로 잘 표현할 때 | `guo2018-natural-language-feedback` |

- **공통점 0개**: 공통점 칩 대신 분위기 가설을 글로 확인한다(2번, 가설은 `describe_selection`). **공통점 1개**: 묻지 않고 그 값 점수만 올린다(2-feedback).
- 3번은 **사용자가 쓴 단어**의 뜻을 맞추고(반응형), 6번은 **시스템이 묻는 값**의 모양을 보여 준다(선제형). 두 방식은 합치지 않는다.
- 여러 축에 걸친 표현("단정한데 딱딱하지 않게", "포근한")은 질문하지 않고 `add_impression`의 축별 가설로 보낸다. 한 축에 값 하나로만 읽히는 표현("미니멀한")은 점선 가설 칩으로 보여 준다.
- 사용자가 "이것보다 밝게"처럼 직접 쓰면 질문 없이 `critique`로 처리한다.
- 정보가 충분하면 질문 대신 비교 제안(`propose_compare`, 흐름 전환)을 낸다. 충분 판정: 핵심 축 빈칸 1개 이하, 요청 후 4턴, "그냥 보여 줘" 중 하나(`가정`).

## 3. 글 고정 상황

LLM이 다른 방식으로 바꿀 수 없다. 사진으로 물으면 답이 애매해지는 상황이다.

| 상황 | 예 | 지금 코드 |
|---|---|---|
| 꼭 지킬 조건끼리 충돌 | "검정만" + "검정은 빼고" | 있음 (`intent.hard_conflict`) |
| 품목 없음 | 무엇을 찾는지 모름 | 있음 (`route` → `ask_clarify`) |
| 기억 저장 동의·변경 | 종료 요약의 저장 범위 ([ADR 0007](../../docs/adr/0007-joint-feedback-and-end-consent.md)) | 종료 요약에 있음 |
| 말과 선택이 부딪힘 | "밝은 색"이라 했는데 어두운 옷을 2번 이상 고름 | 없음 (`가정`) |

## 4. 여러 개가 허용될 때 (규칙 기본값)

LLM이 고르되, 검증에 실패하면 아래 순서의 첫 항목을 쓴다.

```
글 고정(2) > 공통점 칩(4) > 공통점 0개 → 분위기 확인(2)
  > 단어 정렬(3) > 기준 이미지 조정(5)
  > 충분 → 비교 제안
  > 선제형: 축 순위 1위(6절) → 그 축의 기본 방식(7절)
```

## 5. 간격과 개수

| 규칙 | 값 | 근거 |
|---|---|---|
| 한 턴에 나가는 질문 | 1개 | `가정` |
| 반응형 | 간격 규칙의 예외. 행동 직후 바로 묻는다 | `가정` |
| 선제형 | 답 없이 넘긴 질문 뒤에만 2턴 쉰다. 답했으면 다음 턴에 바로 물을 수 있다 | v0 `ASK_GAP`의 의도, `가정` |
| 선제형 상한 | 한 요청에 4개 | `가정` |
| 건너뛰기(명시) | 이번 요청에서 그 축은 다시 묻지 않는다 | 2-feedback 진행 신호 |

## 6. 무엇을 물을지 (선제형 축 순위)

**축 점수 = 중요도 × 분할력 × 불확실성.** 코드가 거르고 남은 축 **전체를 순위와 함께** LLM에 넘긴다. 후보 개수는 고정하지 않는다. 점수 숫자는 넘기지 않는다(LLM이 1위 쪽으로 끌리는 것을 줄인다).

| 요소 | 뜻 | 주체 | 언제 |
|---|---|---|---|
| 중요도 | 이 품목을 고를 때 그 축이 얼마나 중요한가 | 기본값: LLM이 품목별로 오프라인 생성(크롤링한 상품 설명·PI 분포를 입력, 리뷰는 쓰지 않음), 팀 검토. 조정: 대화에서 사용자가 드러낸 축을 LLM이 올림 | 기본값은 품목별 1회, 조정은 매 턴 |
| 분할력 | 남은 적격 상품이 그 축 값으로 얼마나 고르게 나뉘나 (정규화 엔트로피, 0~1) | 코드 (DB 계산) | 매 턴 |
| 불확실성 | 아직 얼마나 모르나 = 1 − 그 축 값 점수 중 최댓값 | 코드 (장기 기억 warm start + 세션 Beta 점수: 직접 말함, 가설, 이미지 선택, 애매한 반응) | 매 턴 |

- **거르기**: Brand, 고정된 축, 이미 물은 축, 건너뛴 축, 남은 상품에서 값이 1종뿐인 축은 순위에서 뺀다.
- **LLM 선택**: 1위가 아닌 축을 고르면 근거 신호가 꼭 있어야 한다(예: 사용자 언급 "구김 안 가는 걸로" → Texture). 신호가 입력에 없으면 1위로 바꾼다.
- 예: "출근용 네이비 셔츠" → Type·Color 고정. 남은 네이비 셔츠가 핏별로 고르게 나뉘고 기억에 핏이 없으면 Fit이 1위. 기억에 "여유 핏"이 있으면 Fit 불확실성이 낮아져 다른 축이 1위가 된다.
- 근거: `christakopoulou2016-question-selection`(질문 고르기). 곱셈 형태와 정규화는 `가정`.

## 7. 어떤 방식으로 (선제형)

### 말로 정하기 쉬운 축

| 판정 | 그렇다면 | 해당 축 | 근거 |
|---|---|---|---|
| ① 사진으로 확인할 수 없나 | 글만 | Fabric, Price, 사이즈, Weight | [ADR 0013](../../docs/adr/0013-langgraph-intent-loop.md) 결정 8, Weight는 `가정` |
| ② 값이 숫자·사실인가 | 글만 | Price, 사이즈, 상황 | v0 "사실·제약은 텍스트" |
| ③ 이름을 들으면 모양이 바로 떠오르나 | 글이 기본, 사진도 허용 | Color, 기본 품목 Type(셔츠·니트·후드) | [ADR 0016](../../docs/adr/0016-pi-v3-value-shapes.md)(색은 대화로 먼저), `guo2018-natural-language-feedback` |
| 셋 다 아님 | 사진 방식 (6 또는 1) | Fit, Length, Tone, Pattern, Style, Texture, Detail, 세부 Type | `가정` |

### 초반·후반 (6번과 1번)

턴 수로 나누지 않는다. **코드가 1번 이미지를 실제로 뽑아 보고, 뽑히면 후반(1번), 안 뽑히면 초반(6번)**이다.

1. 확인된 PI로 적격 상품을 거른다(가설은 쓰지 않는다). 모델이 채운 PI도 쓴다(최종 카탈로그는 모든 상품의 PI가 채워져 있다).
2. 묻는 축의 값별로 묶어 서로 다른 값에서 1장씩, 최대 4장을 뽑는다.
3. 2장 이상 뽑히면 1번, 아니면 6번. Type이 확정되기 전에는 항상 6번이다(셔츠와 니트를 섞어 핏을 비교할 수 없다).

- 예 (후반): "출근용 네이비 셔츠"에서 Fit → 네이비 셔츠를 핏별로 4장 뽑을 수 있다 → 1번. 사용자는 핏 차이만 보고 고른다.
- 예 (초반): "출근할 때 입을 상의"에서 Fit → 핏별 상품이 셔츠·니트·후드로 섞인다 → 6번. 핏 값마다 같은 종류 옷의 대표 사진을 붙인 선택지로 묻는다.

### 축별 기본 방식

| 축 | 초반 | 후반 | 비고 |
|---|---|---|---|
| Type | 6 | 1 | 이름이 익숙한 기본 품목은 2도 허용 |
| Color | 2 | 2 또는 1 | ADR 0016 |
| Tone · Fit · Length | 6 | 1 | 반응형 5로도 조정 |
| Pattern · Style · Texture · Detail | 6 | 1 | |
| Weight | 2 | 2 | 반응형 5로도 조정 |
| Fabric · Price | 2 | 2 | Fabric은 이미지로 묻지 않는다 |

LLM은 기본값을 바꿀 수 있지만 그 축의 허용 방식 안에서만이다.

### 낯선 용어

축·값마다 "낯선 이름" 목록을 두지 않는다. 글 질문에 "그게 뭐예요?", "모르겠어요"처럼 답하면 LLM이 "용어 모름" 신호를 내고, 다음 질문을 6번으로 바꾼다. 사람마다 아는 용어가 달라 고정 목록은 관리가 어렵다(`가정`).

## 8. LLM이 보는 사용자 신호와 근거 어휘

LLM은 결정마다 아래 어휘에서 근거 신호를 1개 이상 댄다. 코드는 신호가 입력 사실과 맞는지 확인한다(예: 모르겠음 0번인데 "모르겠음 반복"이면 거절).

| 신호 | 쪽으로 | 근거 |
|---|---|---|
| "잘 모르겠어요", 짧은 답 반복, 건너뛰기 반복 | 이미지 (6 또는 1) | `knijnenburg2011-user-type-interaction` |
| 용어 모름 ("그게 뭐예요?") | 6 | `가정` |
| 구체적으로 길게 말함 | 글 | `knijnenburg2011-user-type-interaction`, `guo2018-natural-language-feedback` |
| "사진으로 보여 줘" / "그냥 말로 할게" | 사용자가 말한 방식 | `가정` |
| 사용자 언급 (특정 축을 중요하게 말함) | 그 축을 먼저 | `가정` |
| 공통점 있음 / 없음, 뜻이 갈리는 단어, 거의 맞음, 충분, 분할력 | 2절·4절의 해당 방식 | 2절 |

**2-feedback 진행 신호**를 그대로 받는다: 모르겠음 → 그 축을 이미지 방식으로 한 번 더, 건너뛰기 → 이번 요청에서 다시 묻지 않음, 방식 바꾸기 → 바꾼 방식 우선(`decided_by: user`), 다 별로 → 다음은 글로.

## 9. 사건 기반 질문 (#30 결정)

| 질문 | 결정 |
|---|---|
| 행동 직후 질문을 `candidates`에 넣을지, 별도 경로로 둘지 | 같은 후보 목록에 넣고 종류(`kind`)로 구분한다. 빈칸 = 선제형, 행동 = 반응형. LLM 선택·검증·로그가 한 곳에서 돈다 |
| 2턴 간격 규칙과의 관계, 한 턴 질문 개수 | 반응형은 간격의 예외, 선제형만 간격을 지킨다(5절). 한 턴에 질문 1개 |
| 이미지 질문이 8장 그리드를 대신하는지 | 대신한다. 질문하는 턴은 질문 이미지(1·6번, 최대 4장)만, 질문하지 않는 턴은 추천 상품 3~4장만 보인다 (채팅형 화면) |
| "이것보다 더 ~"(5번)의 트리거 | 아래 넷 중 하나 + 순서형 축 빈칸 |

5번 트리거:

| 트리거 | 기준 |
|---|---|
| 1장만 골랐을 때 | 이미지 질문에서 1장만 고름 |
| 공통점 칩 "있으면 좋아요" | 고른 상품 중 사용자가 기준 상품을 고른다 (= 비슷하게 더 둘러보기) |
| 같은 상품이 계속 상위 | 같은 상품이 2턴 연속 추천 1위 (`가정`) |
| 결정 직전 | 사용자가 상품을 후보함에 담았을 때 |

## 10. 사용자가 방식을 바꾸기

- 이미지 질문에도 입력창은 항상 열어 둔다.
- 텍스트 질문에는 [사진으로 볼게요]를 둔다. 그 축의 이미지 방식이 허용될 때만 보인다.
- 사용자가 바꾼 방식을 어디까지 유지할지(그 축만 / 요청 전체)는 B 전에 정한다.

## 11. 결정 로그

질문마다 `{질문 후보, 종류(반응형/선제형), 방식, 결정 주체(규칙/LLM/사용자 전환), 근거 신호, 이유, 허용 목록, 축 순위 상위, 그림자(규칙이 골랐을 결정), 일치 여부, 거절 이유, 프롬프트 버전}`을 남긴다. LLM과 규칙이 갈린 턴에서 사용자가 방식을 직접 바꾼 비율로 어느 쪽이 맞았는지 본다.

## 12. 다른 파트에 넘길 것

- 1 (1-modes.md):
  - 5번 기준 이미지 조정(칩 + 입력창)과 6번 사진 붙은 선택지를 확정 방식으로 옮긴다. 6번 코드 이름을 정한다(여기서는 `photo_chips` 가칭).
  - 3번 단어 정렬과 6번은 합치지 않는다.
  - 1번·6번 선택지는 최대 4개, 1번 필요 조건은 "그 축 값이 다른 적격 상품 2~4장"으로. 2장이면 대조 2장 화면(하나 고르기 + 둘 다 좋아요 / 둘 다 아님)이라 `contrast_pair`는 1번의 2장 형태로 합친다.
  - 공통점 칩 "있으면 좋아요"는 비슷하게 더 둘러보기다. 누르면 고른 상품 중 기준 상품을 사용자가 고른다.
  - 질문 이미지에 모델이 채운 PI도 쓴다.
- 2 (2-feedback.md): 6번 사진 붙은 선택지의 답 반영 행 (다중 선택 값을 L4로 볼지 L3로 볼지, 안 고른 값 L−1 여부).
